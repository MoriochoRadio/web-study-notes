정리하면 이 폴더에는 **두 가지**가 함께 있다.

- **제출 코드** — 이후 본인이 직접 풀어 제출한 코드. PASS.
- **보충 풀이** — 문제를 확인한 뒤 복잡도를 줄여 따로 써 본 코드. 제출한 적 없다.

아래 표와 "로컬 검증" 항목은 이 저장소에서 직접 돌려 본 결과이며, 프로그래머스 채점 화면을 재현한 것이 아니다. 시험 당일의 소요 시간 기록은 없다.

## Java — 약수의 합

- 문제: [프로그래머스 12928](https://school.programmers.co.kr/learn/courses/30/lessons/12928)
- 입력: 0 이상 3000 이하의 정수. 약수의 합을 반환한다.
- 기본 접근: 1부터 n까지 순회하며 나머지가 0인 수를 더한다. 시간 O(n), 추가 공간 O(1).
- **제출 코드**([SubmittedDivisorSum.java](SubmittedDivisorSum.java), PASS): 자기 자신 n을 먼저 더해 두고, 나머지 약수는 `n/2` 이하에만 있다는 성질을 써서 절반만 돈다. 시간 O(n), 추가 공간 O(1).
- **보충 풀이**([Solution.java](Solution.java), 미제출): 약수 d를 찾으면 n/d도 함께 더한다. 완전제곱수에서는 같은 약수를 한 번만 더한다. 시간 O(√n), 추가 공간 O(1).
- `divisor <= n / divisor`를 사용해 제곱 계산을 피했다. 두 코드 모두 n=0일 때 반복하지 않고 0을 반환한다.

> **왜 `n/2`까지만 돌아도 되나** — n 자신을 뺀 약수 중 가장 큰 것은 `n/2`를 넘을 수 없다. n을 2보다 작은 수로 나누면 몫이 n보다 커지기 때문이다. 그래서 n을 먼저 더해 두면 나머지는 `1 ~ n/2`에서만 찾으면 된다. 전수 탐색의 절반이고, √n 풀이보다는 느리지만 제한(3000) 안에서는 충분하다.

| 확인 입력 | 기대 결과 | 확인할 부분 |
|---|---:|---|
| 0 | 0 | 반복이 실행되지 않음 |
| 1 | 1 | 약수 쌍의 중복 방지 |
| 5 | 6 | 소수 |
| 12 | 28 | 여러 약수 쌍 |
| 36 | 91 | 제곱근 6을 한 번만 더함 |
| 3000 | 9360 | 입력 상한 |

[DivisorSumTest.java](DivisorSumTest.java)는 각 수의 배수에 약수를 누적하는 별도 방식으로 기대값을 만들고, **제출 코드와 보충 풀이 둘 다**를 허용 범위 전체 3,001개 입력과 비교한다.

```powershell
javac -encoding UTF-8 Solution.java DivisorSumTest.java
java DivisorSumTest
```

## SQL — 최댓값 구하기

- 문제: [프로그래머스 59415](https://school.programmers.co.kr/learn/courses/30/lessons/59415)
- 대상: `ANIMAL_INS.DATETIME`의 가장 늦은 보호 시작 시각.
- **제출 코드**([max-datetime.sql](max-datetime.sql), PASS): 행을 묶을 필요 없이 `MAX(DATETIME)`을 한 번 계산한다. 아래는 제출한 것과 같은 쿼리를 대문자 표기로 정리한 것이다.

```sql
SELECT MAX(DATETIME) AS 시간
FROM ANIMAL_INS;
```

가장 최근 시각 하나를 구하는 문제이므로 동물 이름이나 ID는 선택하지 않는다. `GROUP BY`를 추가하면 그룹마다 결과가 나와 요구사항이 달라진다. 같은 최댓값을 가진 행이 여러 개여도 집계 결과는 한 행이다. 빈 테이블에서는 NULL 한 행이 나온다. 원문에서 DATETIME은 NOT NULL이다.

[검증 SQL](verify-max-datetime.sql)은 임시 테이블만 사용한다. 날짜 순서가 섞인 자료·최댓값 중복·한 행·빈 집합을 확인하고 임시 테이블을 삭제한다. 문제의 원본 데이터나 기존 수업 테이블을 변경하지 않는다.
