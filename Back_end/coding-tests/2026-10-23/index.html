약수의 개수와 덧셈

JAVA약수 개수i / 2 까지 · √i 까지제곱수 = 약수 홀수 개1 예외

한 줄 요약left부터 right까지 약수 개수가 짝수면 더하고 홀수면 뺀다. 약수는 (1, 16) · (2, 8) · (4, 4)처럼 짝으로 나오므로 개수가 홀수인 수는 가운데 짝이 같은 수 = 제곱수뿐이다. 그래서 약수를 세지 않고 "제곱수면 빼고 아니면 더하기"로도 풀린다.

쉽게 말하면약수는 늘 둘씩 짝지어 춤을 춰요. 16은 (1, 16), (2, 8)에 이어 4가 혼자 거울을 보고 춰서 한 명이 남아요. 짝이 안 맞아 홀수가 되는 건 이렇게 "자기 자신과 짝인 수"가 있는 제곱수뿐이에요.

두 정수 left · right(1 ≤ left ≤ right ≤ 1,000) 사이의 모든 수 중 약수 개수가 짝수면 더하고 홀수면 뺀 값을 반환. 13, 17 → 43(16만 약수 5개라 뺌), 24, 27 → 52(25를 뺌).

JAVA 제출 코드 · 오답노트 원문 (PASS) 
class Solution {
    public int solution(int left, int right) {
        int sum=0;
        for(int i=left;i<=right;i++){
            int count = 2;                 // ← 1과 자기 자신은 항상 약수 — 미리 2개
            if(i==1){
                count=1;                   // ← 1은 1 하나뿐 (1 = 자기 자신)
            }
            for(int j=2;j<=i/2;j++){       // ← 자기 자신 빼고 가장 큰 약수는 i/2 이하
                if(i%j==0){
                    count++;
                }
            }
            if(count % 2 ==0){
                sum+=i;
            }else{
                sum-=i;
            }
        }
        return sum;
    }
}
💡 정답 풀이

제출 코드도 정답이다(1~1,000의 모든 수와 무작위 범위 2,000쌍에서 기댓값과 같음). 원문은 더 빠른 풀이 두 개를 적었다. ① 제곱근까지만 — for (int j = 1; j * j <= i; j++) 나누어떨어지면 짝(j, i / j)이 함께 생기니 count += 2, j * j == i면 짝이 자기 자신이라 +1. 1~1,000 전체에서 안쪽 반복이 제출(2 ~ i/2) 249,001번 → 20,615번으로 준다(로컬 확인). ② 약수를 세지 않기 — 제곱수만 빼기 if (i % Math.sqrt(i) == 0) sum -= i; else sum += i; — 반복 한 번. 실수 나머지로 제곱수를 가리는 식이라 불안해 보이지만, 1부터 1억까지 정수 판별((int) Math.sqrt(i)의 제곱이 i인가)과 비교하니 다른 곳이 없었다(로컬 확인). 뜻이 더 분명한 쓰기: int r = (int) Math.sqrt(i); if (r * r == i) … 제출 코드에서 짚을 곳 1. 1의 예외 처리가 정확하다 — "1과 자기 자신" 2개로 시작하면 1이 2개가 되는데, 1은 그 둘이 같은 수라 1개. 이 한 줄이 없으면 1을 더해 버린다. 2. j <= i / 2 — 자기 자신을 뺀 약수는 i / 2를 넘지 못하니 절반만 돌고 자기 자신은 미리 센 2개에 들어 있다. 범위가 1,000이라 충분하지만 √i까지 줄이면 10배 넘게 빠르다. 흔히 틀리는 곳 1. count = 0에서 j = 2부터 세기 — 1과 자기 자신을 빠뜨린다. 2. ① 방식에서 제곱수를 +2로 세기 — 16이 6개가 되어 홀짝이 뒤집힌다.

📌 주요 개념 정리

(1) 약수는 짝으로 나온다 i % j == 0이면 i / j도 약수. 짝의 작은 쪽은 항상 √i 이하라 √i까지만 보면 전부 찾는다. → 약수 구하기 · 약수의 합 · 카펫(넓이의 약수 짝) (2) 약수 개수가 홀수 ⇔ 제곱수 짝이 같은 수(j * j == i)가 있을 때만 하나가 남는다. "약수 개수의 홀짝"을 묻는 문제는 "제곱수인가"를 묻는 문제다. (3) 반복 범위 줄이기 n → n / 2 → √n. 다음 문제 소수 찾기의 isPrime도 같은 i * i <= n을 쓴다.

소수 찾기

JAVADFS · 백트래킹순열(모든 순서)HashSet 중복 제거isPrime √n

한 줄 요약숫자 종이 조각(최대 7장)으로 만들 수 있는 모든 수를 재귀(DFS)로 만들어 HashSet에 넣고("011"과 "11"은 Integer.parseInt로 같은 11), 그중 소수를 센다. 조각을 썼다고 표시(visited[i] = true)했다가 돌아오면 지우는 백트래킹이 "모든 순서"를 만든다.

쉽게 말하면숫자 카드를 한 장씩 뽑아 줄 세우는 모든 방법을 다 해 보는 거예요. 한 장 뽑아 놓고, 남은 카드로 계속 이어 보고, 다 해 보면 그 카드를 다시 손에 돌려받아 다른 카드로 바꿔 봐요. 같은 수가 여러 번 나와도 바구니(Set)에는 한 번만 들어가요.

🔗 프로그래머스에서 문제 보기

한 자리 숫자가 적힌 종이 조각 문자열 numbers(길이 1~7, 0~9)로 만들 수 있는 소수의 개수. "17" → 3(7, 17, 71), "011" → 2(11, 101 — 11과 011은 같은 수).

📄 정답 풀이 파일 · 📁 29회차 전체 기록

JAVA 오답노트 정답 풀이 (제출 코드 칸은 비어 있음 · 원문 결과 FAIL) 
import java.util.HashSet;

class Solution {
    HashSet<Integer> numberSet = new HashSet<>();   // ← 만든 수 (중복은 저절로 하나)
    boolean[] visited;                                // ← i번 조각을 지금 쓰고 있나

    public int solution(String numbers) {
        visited = new boolean[numbers.length()];
        dfs("", numbers);                             // ← 빈 문자열부터 이어 붙이기
        int count = 0;
        for (int num : numberSet) {
            if (isPrime(num)) count++;
        }
        return count;
    }

    public void dfs(String current, String numbers) {
        if (!current.equals("")) {
            numberSet.add(Integer.parseInt(current)); // ← "011" → 11 (앞의 0 사라짐)
        }
        for (int i = 0; i < numbers.length(); i++) {
            if (!visited[i]) {
                visited[i] = true;                    // ← i번 조각 사용
                dfs(current + numbers.charAt(i), numbers);
                visited[i] = false;                   // ← 돌아오면 반납 (백트래킹)
            }
        }
    }

    public boolean isPrime(int n) {
        if (n < 2) return false;                     // ← 0 · 1 은 소수 아님
        for (int i = 2; i * i <= n; i++) {           // ← √n 까지만
            if (n % i == 0) return false;
        }
        return true;
    }
}
💡 정답 풀이

원문 결과는 FAIL이고 제출 코드 칸은 비어 있다. 실패 원인은 단정하지 않았다. 세 단계 1. 모든 수 만들기 — dfs가 들어올 때마다 지금까지 붙인 문자열을 숫자로 바꿔 넣는다. 그래서 1장 · 2장 · … · 7장짜리 수가 모두 들어간다(부분 순열). 2. 중복 없애기 — "117"처럼 같은 숫자 조각이 있거나 "011" · "11"처럼 앞의 0만 다르면 같은 수가 여러 번 나온다. HashSet<Integer>가 하나로 남긴다. 3. 소수 세기 — isPrime은 2부터 √n까지 나눠 본다. 7장이면 수가 최대 9,999,999라 √ ≈ 3,163번이면 끝난다. 백트래킹이 핵심인 이유 visited[i] = false를 빼면 한 번 쓴 조각을 다시 못 써서, 첫 순서 하나만 끝까지 만들고 다른 순서("71")를 못 만든다. "썼다 → 다음 → 되돌림"이 짝이다. 흔히 틀리는 곳 1. 조합만 만들기 — "17"에서 17만 만들고 71을 빠뜨린다. 순서가 다른 수는 다른 수다. 2. 문자열로 중복 제거 — HashSet<String>이면 "011"과 "11"이 따로 세어진다. 숫자로 바꿔서 넣는다. 3. 0 · 1을 소수로 세기 — n < 2를 먼저 거른다.

📌 주요 개념 정리

(1) DFS로 모든 경우 만들기 재귀 함수 하나가 "하나 고르고 → 나머지로 다시 나를 부르기". 타겟 넘버(+/− 두 갈래)와 같은 뼈대에, 이번엔 "아직 안 쓴 조각" 갈래가 여러 개다. → 게임 맵 최단거리(BFS)와 비교 (2) 백트래킹 = 표시하고 되돌리기 visited[i] = true → 재귀 → visited[i] = false. 같은 조각을 한 순서 안에서 두 번 쓰지 않게 하면서, 다른 순서에서는 다시 쓸 수 있게 한다. (3) Set으로 중복 제거 같은 값은 하나만 — 폰켓몬 · Set 계열. 넣기 전에 "같다"의 기준(Integer 11 vs 문자열 "011")을 정해야 한다. (4) 소수 판별은 √n까지 앞 문제 약수의 개수와 덧셈과 같은 i * i <= n. 많이 판별해야 하면 에라토스테네스의 체로 한 번에 구한다.

한 줄 요약게시글(B)과 회원(U)을 작성자 ID로 JOIN하고, 묶기 전에 WHERE STATUS = 'DONE'으로 거래 완료 글만 남긴 뒤, 회원별로 GROUP BY해 합계가 70만 이상인 그룹만 HAVING으로 남긴다. 정렬은 별칭 TOTAL_SALES로.

SQL 제출 코드 · 오답노트 원문 (PASS) 
SELECT B.WRITER_ID, U.NICKNAME, sum(B.PRICE) AS TOTAL_SALES
from USED_GOODS_BOARD B join USED_GOODS_USER U on B.WRITER_ID = U.USER_ID  -- ← 글쓴이 = 회원
where B.STATUS = 'DONE'                   -- ← 묶기 전: 완료된 거래만
group by B.WRITER_ID                      -- ← 회원별로 (닉네임은 GROUP BY 에 없음 → 아래 💡)
having sum(B.PRICE) >= 700000            -- ← 묶은 뒤: 합계 70만 이상
order by TOTAL_SALES ASC;                 -- ← SELECT 의 별칭을 그대로
💡 정답 풀이

제출 코드도 정답이다(문제 예시 · 검증용 행에서 정답 풀이와 같은 결과). 원문 정답 풀이는 한 줄씩 해설을 단 형식이라, 해설에 적힌 절을 이어 붙이면 SELECT U.USER_ID, U.NICKNAME, SUM(B.PRICE) AS TOTAL_SALES … GROUP BY U.USER_ID, U.NICKNAME HAVING SUM(B.PRICE) >= 700000 ORDER BY TOTAL_SALES ASC. 제출 코드와 다른 두 곳 1. GROUP BY B.WRITER_ID만 쓰고 U.NICKNAME을 SELECT — 표준 SQL은 "집계 함수 밖의 SELECT 열은 모두 GROUP BY에"를 요구한다(원문 개념 정리). MySQL은 ONLY_FULL_GROUP_BY 검사에서도 조인 조건의 =와 기본 키로 값이 하나로 정해지는 열(작성자 ID → 회원 → 닉네임)은 허용한다(함수 종속). 그래서 PASS가 났을 수 있지만, 채점 DB 설정은 알 수 없어 단정하지 않았다. 어디서나 통하게 쓰려면 정답처럼 GROUP BY U.USER_ID, U.NICKNAME. 2. 첫 열 이름 — 제출은 WRITER_ID, 문제 예시는 USER_ID. 값은 같고(조인 조건) 채점은 통과했지만, 결과 열 이름까지 문제와 맞추려면 U.USER_ID나 B.WRITER_ID AS USER_ID. 흔히 틀리는 곳 1. HAVING > 700000 — "이상"이면 >=. 딱 70만인 사람이 빠진다. 2. WHERE STATUS = 'DONE'을 빼기 — 판매 중인 글 금액까지 더해진다. 3. WHERE SUM(PRICE) >= 700000 — WHERE는 묶기 전이라 집계 함수를 못 쓴다(오류). 4. 닉네임으로만 묶기 — 닉네임이 같은 다른 사람이 한 줄로 합쳐진다. 묶는 기준은 ID.

📌 주요 개념 정리

(1) 실행 순서 — FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY 그래서 WHERE엔 집계 함수를 못 쓰고, ORDER BY에선 SELECT의 별칭을 쓸 수 있다. → HAVING vs WHERE · WHERE vs HAVING (2) GROUP BY와 SELECT 열 묶은 뒤 한 줄에는 "그룹마다 하나로 정해지는 값"만 올 수 있다 — 묶은 열이거나 집계 결과. → GROUP BY (3) 같은 표의 다른 문제 15회차 조건에 부합하는 중고거래 상태 조회하기도 USED_GOODS_BOARD · STATUS(SALE · RESERVED · DONE)를 다뤘다. 집계 + 조건은 카테고리 별 도서 판매량 집계하기와 같은 모양. → JOIN

ORDER BY TOTAL_SALES 는 되는데 HAVING TOTAL_SALES >= 700000 은 어떨까?
표준 순서로는 HAVING이 SELECT보다 먼저라 별칭을 모르는 게 원칙이에요. MySQL은 HAVING에서 별칭을 허용하지만 다른 DB에선 오류가 나니 SUM(B.PRICE)를 다시 쓰는 게 안전해요(제출 · 정답 모두 그렇게 씀).

💼 이 유형을 다시 만나면"조건에 맞는 것만 → 사람별로 → 합계가 얼마 이상"은 WHERE → GROUP BY → HAVING 세 칸에 그대로 옮기면 돼요. 묶는 기준은 이름이 아니라 ID로, SELECT의 일반 열은 GROUP BY에도 적어 두면 DB가 바뀌어도 안전합니다.
