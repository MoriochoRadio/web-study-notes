가운데 글자 가져오기

JAVA/ 몫 · % 나머지홀짝 판별charAt · substringchar + char 함정

한 줄 요약길이를 2로 나눈 몫 n / 2가 가운데 자리다. 길이가 홀수면 그 한 글자, 짝수면 그 앞 글자와 함께 두 글자. substring(시작, 끝)은 끝을 포함하지 않으니 짝수는 substring(n/2 - 1, n/2 + 1).

쉽게 말하면줄 선 사람 수가 홀수면 한가운데 한 명, 짝수면 가운데 두 명이에요. 몇 번째 자리인지는 "사람 수 ÷ 2"의 몫으로 바로 나와요(0번부터 세니까).

✅ PASSJAVA28회차 · 2026.10.20
🔗 프로그래머스에서 문제 보기

단어 s(길이 1~100)의 가운데 글자를 반환하는 문제. 길이가 짝수면 가운데 두 글자. "abcde" → "c", "qwer" → "we".

📄 제출 코드 파일 · 📄 정답 풀이 파일 · 📁 28회차 전체 기록

JAVA 제출 코드 · 오답노트 원문 (PASS) 
class Solution {
    public String solution(String s) {
        int cen = s.length() % 2;                 // ← 이미 0(짝수) 또는 1(홀수)
        String st = "";                           // ← 빈 문자열을 앞에 두는 이유는 아래 💡
        if(cen % 2 == 0){                         // ← cen == 0 과 같은 뜻 (% 2 를 한 번 더)
            return st+s.charAt(s.length()/2-1) + s.charAt(s.length()/2);   // ← 짝수: 두 글자
        }else{
            return st+s.charAt(s.length()/2);                             // ← 홀수: 한 글자
        }
    }
}
💡 정답 풀이

제출 코드도 정답이다(무작위 10,000개에서 기댓값과 같음). 원문 정답 풀이는 같은 생각을 substring으로 쓴다. int cen = s.length() / 2; → 짝수면 s.substring(cen - 1, cen + 1), 홀수면 s.substring(cen, cen + 1). 제출 코드에서 짚을 곳 1. st + …가 하는 일 — char끼리 더하면 문자가 붙지 않고 문자 코드가 더해진 정수가 된다. "qwer"에서 s.charAt(1) + s.charAt(2)는 'w'(119) + 'e'(101) = 220(로컬 확인). 앞에 문자열 ""이 있으면 왼쪽부터 문자열 이어 붙이기가 되어 "we". 의도한 것인지와 상관없이 이 한 칸이 정답을 만든다 — "" + a + b 대신 s.substring(…)이나 String.valueOf(a) + b가 뜻이 분명하다. 2. 나머지를 두 번 — cen = s.length() % 2가 이미 0/1이라 cen % 2 == 0은 cen == 0과 같다. 변수 이름 cen(가운데)도 실제로는 "홀짝"이라 읽는 사람이 헷갈린다. 흔히 틀리는 곳 1. substring(cen - 1, cen)처럼 끝을 포함한다고 생각하기 — 한 글자만 나온다(끝 미포함). 2. 짝수 가운데를 n/2, n/2 + 1로 잡기 — 0부터 세므로 n/2 - 1, n/2가 맞다("qwer"는 1 · 2번).

공식 예제 abcde → c · qwer → we                       → 제출 코드 · 정답 풀이 모두 통과
무작위 10,000개 (길이 1~100, 영문 · 한글)               → 둘 다 기댓값과 같음
(함정) "" 없이 q.charAt(1) + q.charAt(2)              → 220  (char + char = int)

📌 주요 개념 정리

(1) / 와 % 정수끼리 /는 몫(5 / 2 = 2), %는 나머지(5 % 2 = 1). 홀짝은 n % 2 == 0. 같은 날 시작한 파이썬에서는 몫이 //, /는 실수(py-02). → ☕ 7. 연산자 (2) 문자열 인덱스 — 0부터 길이 − 1까지 charAt(i)는 한 글자(char), substring(a, b)는 a부터 b 앞까지의 문자열. 범위를 벗어나면 StringIndexOutOfBoundsException. → String 주요 메서드 · 문자열 자르기 (3) char는 숫자다 char + char → int, String + char → String. 연산은 왼쪽부터라 a + b + ""는 숫자 합 뒤에 문자열이 붙는다. → 형 변환 총정리

한 줄 요약2021년 가입(YEAR(JOINED) = 2021) 그리고 20~29세(AGE BETWEEN 20 AND 29)인 행을 COUNT(*)로 센다. BETWEEN은 양 끝을 포함하고, 나이가 NULL인 회원은 비교가 참이 아니라 저절로 빠진다.

카펫

JAVA완전 탐색약수 (total % h == 0)(가로−2)×(세로−2) = 노랑세로를 작은 쪽부터

한 줄 요약전체 칸 수 total = brown + yellow = 가로 × 세로. 세로 h를 3부터 하나씩 올리며 total을 나누어떨어지게 하는 가로 w = total / h를 구하고, 테두리를 뺀 안쪽 (w − 2) × (h − 2)가 yellow와 같으면 답 [w, h].

쉽게 말하면타일이 모두 몇 장인지는 알아요. 그러면 "세로가 3줄이면 가로는 몇 줄?", "4줄이면?" 하고 하나씩 맞춰 보다가, 바깥 한 줄을 벗겨 낸 안쪽 타일 수가 노란 타일 수와 같아지는 순간이 답이에요.

❌ FAILJAVA28회차 · 2026.10.20
🔗 프로그래머스에서 문제 보기

가운데는 노란색, 테두리 1줄은 갈색인 격자 카펫. 갈색 수 brown(8~5,000), 노란색 수 yellow(1~2,000,000)로 카펫의 [가로, 세로]를 반환(가로 ≥ 세로). 10, 2 → [4, 3], 24, 24 → [8, 6].

📄 정답 풀이 파일 · 📁 28회차 전체 기록

JAVA 오답노트 정답 풀이 (제출 코드 칸은 비어 있음 · 원문 결과 FAIL) 
class Solution {
    public int[] solution(int brown, int yellow) {
        int total = brown + yellow;                  // ← 전체 넓이 = 가로 × 세로

        for (int h = 3; h <= total; h++) {           // ← 세로는 최소 3 (테두리 위아래 + 노랑 1줄)
            if (total % h == 0) {                    // ← 나누어떨어져야 가로가 정수
                int w = total / h;
                if ((w - 2) * (h - 2) == yellow) {   // ← 테두리를 벗긴 안쪽 = 노랑
                    return new int[] { w, h };
                }
            }
        }
        return new int[] {};
    }
}
💡 정답 풀이

원문 결과는 FAIL이고 제출 코드 칸은 비어 있다. 실패 원인은 단정하지 않았다. 규칙 두 개 1. 가로 × 세로 = brown + yellow(전체 넓이). 2. 노랑은 가운데에 뭉쳐 있고 갈색이 한 줄 감싸므로 (가로 − 2) × (세로 − 2) = yellow. 왜 세로를 3부터 "올라가며" 찾나 가로 · 세로 짝은 바꿔도 넓이가 같아서, 세로를 큰 쪽부터 내려가면 처음 맞는 것이 가로 < 세로인 짝이 된다(24/24 → [6, 8], 로컬 확인). 작은 쪽부터 올라가면 처음 맞는 h가 짧은 변이라 문제 조건(가로 ≥ 세로)이 저절로 지켜진다. 답이 하나뿐이라 짧은 변까지만 돌고 끝난다. 흔히 틀리는 곳 1. 세로를 1이나 2부터 — 노랑이 들어갈 자리가 없다. h − 2 ≥ 1이라 최소 3. 2. 나누어떨어지는지 확인 없이 w = total / h — 정수 나눗셈이 버림이라 넓이가 안 맞는 가로가 나온다. 3. 갈색 식으로만 풀기 — 2 × 가로 + 2 × 세로 − 4 = brown도 맞지만, 노랑 조건을 함께 봐야 하나로 정해진다.

📌 주요 개념 정리

(1) 완전 탐색 — 범위가 작으면 다 해 본다 세로는 √(total)까지만 보면 되고 total ≤ 2,005,000이라 많아야 약 1,400번. → 타겟 넘버(모든 경우) · 게임 맵 최단거리(BFS) (2) 약수 — total % h == 0 가로 · 세로는 넓이의 약수 짝. 약수는 짝으로 나오니 작은 쪽만 돌면 된다. → 약수 구하기 · 약수의 합 (3) 식으로 풀기(다른 방법) 가로 + 세로 = brown / 2 + 2, 가로 × 세로 = total이라 두 수의 합과 곱을 아는 이차방정식이다. 반복문 없이 근의 공식으로도 풀 수 있다(실행하지 않은 설명).

대장균들의 자식의 수 구하기

SQL셀프 조인LEFT JOIN으로 0 살리기COUNT(열) vs COUNT(*)GROUP BY

한 줄 요약같은 표를 두 번 쓴다 — 왼쪽 E1은 "나", 오른쪽 E2는 "내 ID를 부모로 가진 개체". LEFT JOIN … ON E1.ID = E2.PARENT_ID로 자식을 옆에 붙이고 GROUP BY E1.ID로 묶어 COUNT(E2.ID)로 센다. 자식이 없으면 E2가 NULL이라 0.

쉽게 말하면가족 명부 한 장을 복사해 두 장을 나란히 놓고, 왼쪽 사람마다 "부모 칸에 내 번호가 적힌 사람"을 오른쪽에서 모두 찾아 옆에 붙여요. 붙은 사람 수가 자식 수, 아무도 없으면 빈칸이라 0명이에요.

🔗 프로그래머스에서 문제 보기

ECOLI_DATA(ID · PARENT_ID — 최초 개체는 NULL · …)에서 개체 ID와 자식 수 CHILD_COUNT를 출력. 자식이 없으면 0, ID 오름차순. 예시 6개체 → 1|1, 2|2, 3|0, 4|1, 5|0, 6|0.

📄 정답 풀이 파일 · 📁 28회차 전체 기록

SQL 오답노트 정답 풀이 (제출 코드 칸은 비어 있음 · 원문 결과 FAIL) 
SELECT E1.ID, COUNT(E2.ID) AS CHILD_COUNT     -- ← NULL(자식 없음)은 세지 않음 → 0
FROM ECOLI_DATA E1                             -- ← "나" (모든 개체가 기준)
LEFT JOIN ECOLI_DATA E2 ON E1.ID = E2.PARENT_ID -- ← 내 ID를 부모로 가진 개체 = 내 자식
GROUP BY E1.ID                                 -- ← 나 하나당 한 줄로 묶기
ORDER BY E1.ID ASC;
💡 정답 풀이

원문 결과는 FAIL이고 제출 코드 칸은 비어 있다. 실패 원인은 단정하지 않았다. 원문 해설의 표현대로 ON은 "내 ID를 부모로 가진 자식들을 내 옆에 다 끌어모아라", GROUP BY는 "나를 기준으로 모인 자식들을 한 덩어리로", COUNT는 "덩어리마다 몇 명". LEFT JOIN만 한 중간 결과(예시 6행) — 1|3, 2|4, 2|5, 3|NULL, 4|6, 5|NULL, 6|NULL. 자식이 둘이면 두 줄, 없으면 오른쪽이 NULL인 한 줄로 살아남는다. 여기서 ID별로 묶어 NULL이 아닌 것만 세면 답이다. 흔히 틀리는 곳 (모두 실행해 확인) 1. INNER JOIN — 짝이 없는 3 · 5 · 6이 사라져 3행만 남는다. "0으로 출력"하려면 LEFT. 2. COUNT(*) — NULL로 붙은 한 줄도 행이라 자식 없는 개체가 1이 된다. 오른쪽 표의 열(COUNT(E2.ID))을 세야 0. 3. ON의 방향을 반대로(E1.PARENT_ID = E2.ID) — "내 부모"를 붙이게 되어 자식 수가 아니라 부모가 있는지(0/1)를 센다.

자식이 2명 이상인 개체만 보려면 무엇을 더할까?
GROUP BY E1.ID HAVING COUNT(E2.ID) >= 2. 묶은 뒤의 조건은 WHERE가 아니라 HAVING이에요(예시에서는 ID 2만 — 실행해 확인).
LEFT JOIN 뒤 WHERE E2.ID IS NULL 만 남기면 무엇이 될까?
자식이 없는 개체(예시에서 3 · 5 · 6)예요. "짝이 없는 것 찾기"의 대표 모양입니다 — 중간 결과에서 오른쪽이 NULL인 줄이 그것이에요.

💼 이 유형을 다시 만나면"항목마다 딸린 것의 개수(0 포함)"는 LEFT JOIN + GROUP BY + COUNT(오른쪽 열) 세트예요 — 글마다 댓글 수, 회원마다 주문 수, 카테고리마다 상품 수. 오늘 배운 Pandas로는 df.groupby("PARENT_ID").size()로 자식 수를 세고 reindex(df.ID, fill_value=0)로 0을 채우는 방식이 같은 일을 해요(예시로 실행하면 [1, 2, 0, 1, 0, 0]).
