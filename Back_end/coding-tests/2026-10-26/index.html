문자열 내림차순으로 배치하기

JAVAtoCharArrayArrays.sort(char[])StringBuilder.reverse대문자 < 소문자

한 줄 요약문자열은 정렬 메서드가 없으니 toCharArray()로 char[]를 만들어 Arrays.sort(오름차순)한 뒤, new StringBuilder(new String(arr)).reverse().toString()으로 뒤집어 내림차순을 만든다. 문자 코드로 비교하므로 대문자(65~90)가 소문자(97~122)보다 작다 — "Zbcdefg" → "gfedcbZ".

쉽게 말하면글자 카드를 사전 순서로 한 줄 세운 다음, 줄의 맨 끝 카드부터 거꾸로 읽는 거예요. 사전에서 대문자가 소문자 앞에 놓여 있어서, 거꾸로 읽으면 대문자는 맨 뒤로 가요.

import java.util.Arrays;

class Solution {
    public String solution(String s) {
        char[] charArray = s.toCharArray();           // ← String 은 정렬 못 함 → char 배열로
        Arrays.sort(charArray);                       // ← 오름차순 (문자 코드 순)
        return new StringBuilder(new String(charArray)) // ← 배열 → 문자열 (toString() 이 아님!)
                .reverse().toString();                // ← 뒤집으면 내림차순
    }
}

동명 동물 수 찾기

SQLGROUP BYHAVING COUNTCOUNT(*) vs COUNT(열)이름 NULL 제외

한 줄 요약이름별로 묶고(GROUP BY NAME) 개수를 센 뒤 묶은 결과에서 2 이상만 남긴다(HAVING). 이름이 없는(NULL) 동물은 집계에서 빼야 하는데, HAVING count(NAME) >= 2는 count(열)이 NULL을 세지 않아 NULL 그룹이 저절로 빠진다.

쉽게 말하면보호소 명단에서 같은 이름끼리 한 상자에 담고, 상자 안 동물이 두 마리 이상인 상자만 이름순으로 내보내요. 이름표가 없는 동물들도 한 상자에 담기는데, "이름이 적힌 동물 수"를 세면 0이라 탈락해요.

💡 정답 풀이

제출 코드도 정답이다(문제 예시 6행과 검증용 행에서 의도한 결과). 원문 정답 풀이 칸은 비어 있다. 이 코드가 NULL 이름을 빼는 방법 GROUP BY NAME은 NULL끼리도 한 그룹으로 묶는다. 이름이 NULL인 동물이 둘이면 그 그룹의 count(*)는 2지만 count(NAME)은 0이라 >= 2를 못 넘는다. 그래서 따로 WHERE NAME IS NOT NULL을 쓰지 않아도 제외된다. 짚을 곳 1. HAVING count(*) >= 2로 쓰면 — 이름 없는 두 마리가 NULL | 2 행으로 들어온다(로컬 확인). count(*)로 세려면 WHERE NAME IS NOT NULL을 함께 써야 한다. 2. 별칭 'COUNT' — 작은따옴표로 감싼 별칭도 MySQL에서 되지만 정석은 백틱(`COUNT`)이나 따옴표 없는 AS COUNT. 함수 이름 count와 같아 헷갈릴 수 있다. 3. 대소문자 — SQLite는 Lucy와 lucy를 다른 이름으로 묶는다. MySQL 기본 콜레이션은 대소문자를 무시해 같은 이름으로 묶는다(문서 기준 — 이 PC에서 MySQL로는 확인하지 않음). 로컬에서는 COLLATE NOCASE로 같은 동작을 재현했다. 흔히 틀리는 곳 1. WHERE count(*) >= 2 — 묶기 전이라 집계 함수를 못 쓴다(오류, 로컬 확인). 2. > 2 — "두 번 이상"은 >= 2. 2마리인 이름이 빠진다. 3. 이름 순 정렬을 빼먹기 — 문제가 ORDER BY NAME을 요구한다.

H-Index

JAVA정렬 후 탐색h = n − i처음 만족 = 최댓값정의 읽기

한 줄 요약인용 횟수를 오름차순으로 정렬하면 citations[i] 뒤(자신 포함)에 남은 논문 수가 n - i다. 그 논문의 인용 횟수가 n - i 이상이면 "h번 이상 인용된 논문이 h편 이상"인 h = n - i가 성립한다. i를 앞에서부터 늘리면 h는 줄어드니 처음 성립하는 순간의 h가 최댓값이고, 끝까지 없으면 0.

쉽게 말하면성적 낮은 사람부터 줄 세워 놓고 "나보다 점수가 같거나 높은 사람이 나 포함 몇 명이지?"를 앞에서부터 물어요. 처음으로 "내 점수 ≥ 그 인원 수"가 되는 순간의 인원 수가 답이에요. 줄이 점수순이라 일일이 세지 않아도 돼요.

❌ FAILJAVA30회차 · 2026.10.26
🔗 프로그래머스에서 문제 보기

논문 n편의 인용 횟수 배열 citations(1~1,000편, 각 0~10,000회)에서, h번 이상 인용된 논문이 h편 이상이고 나머지 논문은 h번 이하 인용되었을 때 h의 최댓값(H-Index). [3, 0, 6, 1, 5] → 3.

📄 정답 풀이 파일 · 📁 30회차 전체 기록

JAVA 오답노트 정답 풀이 (제출 코드 칸은 비어 있음 · 원문 결과 FAIL) 
import java.util.Arrays;

class Solution {
    public int solution(int[] citations) {
        Arrays.sort(citations);                  // ← 오름차순: [3, 0, 6, 1, 5] → [0, 1, 3, 5, 6]
        int n = citations.length;

        for (int i = 0; i < n; i++) {
            int h = n - i;                       // ← i번째(포함) 뒤에 남은 논문 수
            if (citations[i] >= h) {             // ← 이 논문조차 h번 이상 → 남은 h편 모두 h번 이상
                return h;                        // ← 처음 성립하는 h 가 가장 크다
            }
        }
        return 0;                                // ← 한 번도 성립하지 않으면 (모두 0회 인용)
    }
}
💡 정답 풀이

원문 결과는 FAIL이고 제출 코드 칸은 비어 있다. 실패 원인은 단정하지 않았다. 원문 정답 풀이의 해설을 따라 한 줄씩 풀면 아래와 같다. 예시 [0, 1, 3, 5, 6](n = 5) - i = 0: h = 5, 0 >= 5? 거짓 · i = 1: h = 4, 1 >= 4? 거짓 - i = 2: h = 3, 3 >= 3? 참 → 3. 3 이후(3 · 5 · 6)는 모두 3번 이상 인용, 앞의 둘(0 · 1)은 3번 이하라 정의와 맞는다. 왜 "처음 성립 = 최댓값"인가 i가 커질수록 h = n − i는 줄어든다. 가장 큰 h부터 시험하고 있으니 처음 맞는 것이 최댓값이다. 정렬해 두었기 때문에 "h번 이상 인용된 논문이 몇 편인지"를 따로 세지 않고 n − i로 바로 안다(원문 메모: "정렬해놔서 갯수를 안 세도 되는거임"). 경계 (로컬 확인) [0] → 0 · [1] → 1 · [100] → 1(논문이 한 편이면 최대 1) · [0, 0, 0] → 0 · [4, 4, 4, 4] → 4 · 1,000편이 모두 10,000회 → 1000(h는 논문 수를 넘지 못한다). 흔히 틀리는 곳 1. 정의 읽기 — "인용 횟수의 최댓값"이나 "정렬한 가운데 값"이 아니다. 가운데 값은 공식 예제에선 우연히 맞지만 [10, 8, 5, 4, 3](답 4)에서는 5가 된다. 2. return 0을 빼먹기 — 모든 논문이 0회면 반복 안에서 한 번도 반환하지 않아 컴파일 오류가 난다(반환문 필요). 3. 정렬 방향 — 내림차순으로 정렬했다면 citations[i] >= i + 1인 마지막 i를 찾는 식으로 바뀐다. 오름차순과 섞어 쓰면 틀린다. 4. h를 n보다 크게 잡기 — h는 논문 수 이하여야 한다.

📄 정답 풀이 파일 · 📁 30회차 전체 기록

SQL 오답노트 정답 풀이 (제출 코드 칸은 비어 있음 · 원문 결과 FAIL) 
SELECT
    CONCAT('/home/grep/src/', F.BOARD_ID, '/', F.FILE_ID, F.FILE_NAME, F.FILE_EXT) AS FILE_PATH
    -- ← 슬래시는 폴더(게시글 ID) 뒤에만. 파일 ID · 이름 · 확장자는 붙여서
FROM USED_GOODS_BOARD B
JOIN USED_GOODS_FILE F ON B.BOARD_ID = F.BOARD_ID          -- ← 게시글 ↔ 첨부파일
WHERE B.VIEWS = (SELECT MAX(VIEWS) FROM USED_GOODS_BOARD)  -- ← 조회수 1등 게시글
ORDER BY F.FILE_ID DESC;                                    -- ← 파일 ID 내림차순

원문 결과는 FAIL이고 제출 코드 칸은 비어 있다. 실패 원인은 단정하지 않았다. 원문 해설은 줄마다 "경로 · JOIN · 서브쿼리 · 정렬"을 설명하고, 아래는 같은 SQL을 돌려 본 결과다. 한 줄씩 1. CONCAT(…) — 열과 글자를 순서대로 이어 하나의 문자열로. 문제의 경로 규칙을 그대로 옮긴다. 2. JOIN … ON B.BOARD_ID = F.BOARD_ID — 파일이 어느 게시글 것인지 연결. 3. WHERE B.VIEWS = (SELECT MAX(VIEWS) …) — 단일 값을 돌려주는 서브쿼리. MAX는 묶기 전 WHERE에서 직접 못 쓰니 괄호 안에서 구해 비교한다. 4. ORDER BY F.FILE_ID DESC. 짚을 곳 1. 문제 예시의 출력 순서 — 본문은 "FILE ID 내림차순"인데 문제 페이지의 예시 출력에는 IMG_000001이 IMG_000002보다 먼저 나와 있다. 이 SQL을 예시 데이터에 돌리면 내림차순이라 IMG_000002가 먼저 나온다(로컬 확인, 오름차순으로 바꾸면 예시의 순서). 채점이 어느 쪽을 기준으로 하는지는 확인하지 못했고, 이 FAIL의 원인이라고 단정하지 않는다. 2. 1등이 둘이면 — = (SELECT MAX …)는 두 게시글의 파일을 모두 돌려주고, ORDER BY VIEWS DESC LIMIT 1은 하나만 고른다. 문제는 "하나만 존재"를 보장하므로 둘 다 같지만 성격이 다르다. 3. FILE_ID는 문자열 — 정렬이 글자 순이라 자릿수가 다르면(IMG_9 vs IMG_10) 숫자 순과 달라진다. 문제 데이터는 IMG_000001처럼 자릿수가 같아 괜찮다(로컬 확인). 흔히 틀리는 곳 1. 경로에서 게시글 ID 뒤 '/'를 빼기 — /home/grep/src/B0001IMG_000002photo2.jpg가 된다(로컬 확인). 2. WHERE B.VIEWS = MAX(B.VIEWS) — 집계 함수는 WHERE에 못 쓴다(오류, 로컬 확인). 서브쿼리가 필요하다. 3. 조회수 조건 없이 JOIN만 — 모든 게시글의 파일(예시 5개)이 나온다. 4. CONCAT에 열 이름 대신 글자를 넣기 — 'FILE_ID'처럼 따옴표를 붙이면 열 값이 아니라 글자 그대로 붙는다.

조회수 최댓값을 서브쿼리 없이, JOIN 한 줄로 알아내려면?
자기 자신과 조인해 "나보다 조회수 높은 글이 없는 글"을 찾거나(LEFT JOIN … ON B2.VIEWS > B.VIEWS … WHERE B2.BOARD_ID IS NULL), 정렬해 한 줄만 가져와요(ORDER BY VIEWS DESC LIMIT 1). 서브쿼리가 가장 읽기 쉬워요.

INNER JOIN이라 파일이 하나도 없는 게시글은 결과에 행이 없어요 → 0행이에요. 파일이 없는 게시글도 보이게 하려면 LEFT JOIN이 필요한데, 이 문제는 "첨부파일 경로"를 묻기 때문에 0행이 맞는 답이에요.
