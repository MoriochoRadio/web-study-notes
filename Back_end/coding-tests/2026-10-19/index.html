제일 작은 수 제거하기

JAVA최솟값 한 번 훑기새 배열 + 따로 세는 index원래 순서 유지빈 배열이면 [-1]

한 줄 요약배열을 한 번 훑어 가장 작은 값을 찾고, 다시 한 번 훑으며 그 값만 건너뛰고 나머지를 길이가 하나 작은 새 배열에 차례로 담는다. 원소가 하나뿐이면 빼고 나면 비니 [-1]을 먼저 돌려준다. 정렬은 쓰지 않는다 — 원래 순서가 깨진다.

쉽게 말하면줄 서 있는 사람 중 키가 제일 작은 한 명만 빼는 문제예요. 키 순서로 다시 줄 세우면(정렬) 안 되고, 한 번 둘러봐서 제일 작은 사람을 기억한 뒤, 그 사람만 빼고 나머지는 원래 순서대로 새 줄에 세우면 됩니다.

🔗 프로그래머스에서 문제 보기

정수 배열 arr(길이 1 이상, 원소는 모두 다름)에서 가장 작은 수를 제거한 배열을 반환하는 문제. 남는 것이 없으면 [-1]. [4,3,2,1] → [4,3,2], [10] → [-1].

📄 정답 풀이 파일 · 📁 27회차 전체 기록

JAVA 오답노트 정답 풀이 (제출 코드 칸은 비어 있음 · 원문 결과 FAIL) 
class Solution {
    public int[] solution(int[] arr) {
        if (arr.length <= 1) {                  // ← 빼고 나면 빈 배열 → [-1] 먼저
            return new int[] {-1};
        }

        int min = arr[0];                       // ← 첫 원소를 임시 최솟값으로
        for (int i = 1; i < arr.length; i++) {
            if (arr[i] < min) {
                min = arr[i];
            }
        }

        int[] ans = new int[arr.length - 1];    // ← 하나 작은 새 배열 (자바 배열은 크기 고정)
        int index = 0;                          // ← 새 배열에 채울 자리는 따로 센다
        for (int i = 0; i < arr.length; i++) {
            if (arr[i] == min) {
                continue;                       // ← 최솟값만 건너뛰고
            }
            ans[index++] = arr[i];              // ← 나머지는 원래 순서대로
        }
        return ans;
    }
}
💡 정답 풀이

원문 결과는 FAIL이고 제출 코드 칸은 비어 있다. 위 코드는 원문의 정답 풀이(주석 포함)로, 실패 원인은 기록만으로 알 수 없어 단정하지 않았다. 풀이의 세 단계 1. 예외 먼저 — 길이가 1이면 계산할 것 없이 {-1}. 2. 최솟값 찾기 — arr[0]에서 시작해 더 작은 값을 만나면 바꾼다(O(n), 한 번). 3. 걸러 담기 — 길이 n − 1 배열을 만들고, 최솟값은 continue, 나머지는 ans[index++]. 원래 배열의 i와 새 배열의 index가 따로 움직이는 것이 핵심. 흔히 틀리는 곳 1. 정렬부터 하기 — Arrays.sort 후 맨 앞을 빼면 [4,3,2,1] → [2, 3, 4]. 예시 답 [4, 3, 2]와 순서가 달라진다(로컬에서 확인). 2. 최솟값을 0에서 시작 — 원소가 모두 양수면 min이 0으로 남아 아무것도 건너뛰지 않고, 길이 2짜리 배열에 3개를 넣다가 ArrayIndexOutOfBoundsException([5,7,9]로 확인). 시작값은 arr[0]이나 Integer.MAX_VALUE. 3. 빈 배열을 그대로 돌려주기 — [10]이면 new int[0]이 아니라 [-1]. 4. "원소가 모두 다르다"를 놓치기 — 이 조건 덕분에 == min으로 건너뛰는 것이 정확히 하나다. 조건 밖 입력 [1,1,2]를 넣으면 두 개를 다 건너뛰어 [2, 0](끝에 빈칸 0)이 나온다.

실행 결과다른 방법(스트림)으로 구한 값과 비교 먼저 예측 → 펼쳐서 확인 
공식 예제 [4,3,2,1] → [4, 3, 2] · [10] → [-1]                         → 통과
무작위 5,000개 (길이 1~20, 서로 다른 -1000~1000)                          → 스트림으로 최솟값을 걸러 낸 값과 같음
(틀린 방법) 정렬 후 맨 앞 빼기 [4,3,2,1]                                  → [2, 3, 4]  순서가 깨짐
(틀린 방법) min = 0 으로 시작 [5,7,9]                                     → ArrayIndexOutOfBoundsException
(조건 밖) 최솟값이 두 개 [1,1,2]                                          → [2, 0]
기댓값은 원문 풀이와 다른 코드예요 — Arrays.stream(arr).min()으로 최솟값을 구하고 filter(v -> v != min)로 걸러, 비면 [-1](시드 27 고정). min = 0 실험은 따로 만든 코드로 돌렸어요. 로컬 검증이며 프로그래머스 재채점은 아닙니다.
📌 주요 개념 정리

(1) 정렬과 원래 순서 "가장 작은 것"이라는 말에 끌려 정렬하면 인덱스와 순서가 모두 바뀐다. 답에 원래 순서가 남아야 하면 정렬하지 말고 골라 건너뛰기. → 여러 기준으로 정렬하기(정렬이 답일 때) (2) 최솟값 패턴 — 첫 원소에서 시작 int min = arr[0]; for (i = 1 …) if (arr[i] < min) min = arr[i]; — 한 번 훑기(O(n)). 시작값을 임의의 숫자(0)로 두면 데이터에 따라 틀린다. (3) 크기가 고정된 배열 — 새로 만들고 자리를 따로 센다 자바 배열은 늘이거나 줄일 수 없어 new int[n - 1]로 새로 만들고, 채울 위치 index를 별도로 관리한다. 크기를 미리 모르면 ArrayList에 담고 마지막에 배열로. → 배열 vs 컬렉션 · 배열 선언 3가지 (4) 예외 입력부터 "빈 배열이면 −1" 같은 조건은 본 계산 전에 return으로 먼저 처리하면 아래 코드가 단순해진다.

답을 펼치기 전에 머릿속으로 먼저 대답해 보세요. 오답노트는 다시 떠올려 봐야 내 것이 됩니다.

[3, -5, 8, 0] 이면 답은?
[3, 8, 0]. 최솟값은 −5이고, 나머지는 원래 순서 그대로예요. 음수가 있어도 arr[0]에서 시작하면 문제없어요.
int min = 0 으로 시작하면 [5, 7, 9] 에서 왜 오류가 날까?
5 · 7 · 9 모두 0보다 커서 min이 0으로 남고, 아무것도 건너뛰지 않아 길이 2인 ans에 3개를 넣다가 세 번째(ans[2])에서 ArrayIndexOutOfBoundsException이 나요.

💼 이 유형을 다시 만나면"하나를 빼고 나머지는 그대로"는 찾기 → 걸러 담기 두 번 훑기예요. 같은 날 시작한 파이썬으로는 m = min(arr) 뒤 [x for x in arr if x != m] or [-1] 한 줄(빈 리스트는 거짓이라 or 뒤로 넘어감)로 같은 답이 나와요([4,3,2,1] → [4, 3, 2], [10] → [-1] 확인) — 🐍 리스트 컴프리헨션. min(arr)을 컴프리헨션 안에 쓰면 원소마다 다시 계산하니 밖에서 한 번만.

SELECT PT_NAME, PT_NO, GEND_CD, AGE,
       COALESCE(TLNO, 'NONE') AS TLNO        -- ← NULL 이면 'NONE' (별칭으로 열 이름 유지)
FROM PATIENT
WHERE AGE <= 12 AND GEND_CD = 'W'            -- ← 두 조건 모두 (12세 포함 → <=)
ORDER BY AGE DESC, PT_NAME ASC;              -- ← 나이 내림차순, 같으면 이름 오름차순

COALESCE(NULL, NULL, '010', 'NONE') 의 결과는?
'010'. 왼쪽부터 보며 처음으로 NULL이 아닌 값을 돌려줘요. 그래서 "휴대폰 → 집 전화 → 'NONE'"처럼 여러 후보를 차례로 쓸 수 있어요(IFNULL · NVL은 두 개만).
WHERE TLNO = NULL 은 왜 0행일까?
NULL은 "모르는 값"이라 NULL = NULL도 참이 아니라 UNKNOWN이에요. WHERE는 참인 행만 남기니 0행. NULL인지 볼 때는 IS NULL · IS NOT NULL.

💼 이 유형을 다시 만나면"없는 값은 OO로 표시"는 화면 · 리포트 쿼리의 단골이에요. 다만 바꾼 값('NONE')은 보여 줄 때만 — 저장하는 데이터는 NULL로 두어야 "정말 모름"과 "NONE이라는 값"을 구분할 수 있어요. 오늘 시작한 파이썬에서는 같은 일을 tlno if tlno is not None else "NONE"(삼항)이나 Pandas의 fillna("NONE")으로 해요.

게임 맵 최단거리

JAVABFS · 큐(Queue)방향 벡터 dx · dy맵에 거리 기록 = 방문 표시도달 못 하면 -1

한 줄 요약출발 칸에서 가까운 칸부터 차례로 퍼져 나가는 너비 우선 탐색(BFS). 큐에서 칸을 하나 꺼내(poll) 상하좌우 네 칸을 보고, 맵 안이고 처음 가는 길(값 1)이면 maps[nx][ny] = maps[x][y] + 1로 거리를 적고 큐에 넣는다. 끝나고 도착 칸의 값이 답, 여전히 1이면 못 간 것이라 -1.

쉽게 말하면출발점에 물을 부으면 물이 한 칸씩 동시에 번져 나가죠. 칸마다 "물이 몇 번째에 도착했는지"를 적어 두면, 도착 칸에 처음 물이 닿은 숫자가 곧 가장 짧은 거리예요. 큐는 "다음에 물이 번질 칸 목록"입니다.

0(벽) · 1(길)로 된 n × m 맵(각 1~100, 둘 다 1인 경우는 없음)에서 왼쪽 위 (1, 1)에서 오른쪽 아래 (n, m)까지 동서남북 한 칸씩 움직일 때 지나는 칸 수의 최솟값(출발 · 도착 칸 포함)을 반환하는 문제. 도착할 수 없으면 -1. 예시 5 × 5 맵 → 11.

📄 정답 풀이 파일 · 📁 27회차 전체 기록

JAVA 오답노트 정답 풀이 (제출 코드 칸은 비어 있음 · 원문 결과 FAIL · 주석 줄임) 
import java.util.Queue;
import java.util.LinkedList;

class Solution {
    public int solution(int[][] maps) {
        int n = maps.length, m = maps[0].length;
        int[] dx = {-1, 1, 0, 0};                  // ← 상 하 좌 우 (행 변화)
        int[] dy = {0, 0, -1, 1};                  //              (열 변화)

        Queue<int[]> queue = new LinkedList<>();   // ← 다음에 볼 칸 목록 (먼저 넣은 것부터)
        queue.add(new int[]{0, 0});

        while (!queue.isEmpty()) {
            int[] current = queue.poll();          // ← 가장 먼저 들어온(가까운) 칸
            int x = current[0], y = current[1];
            for (int i = 0; i < 4; i++) {
                int nx = x + dx[i], ny = y + dy[i];
                if (nx < 0 || nx >= n || ny < 0 || ny >= m) continue;    // ← 맵 밖 (먼저 검사!)
                if (maps[nx][ny] == 0 || maps[nx][ny] > 1) continue;    // ← 벽 · 이미 간 곳
                maps[nx][ny] = maps[x][y] + 1;                          // ← 거리 기록 = 방문 표시
                queue.add(new int[]{nx, ny});
            }
        }
        int answer = maps[n - 1][m - 1];
        return answer == 1 ? -1 : answer;          // ← 1 그대로면 한 번도 못 닿음
    }
}
💡 정답 풀이

원문 결과는 FAIL이고 제출 코드 칸은 비어 있다. 위 코드는 원문 정답 풀이에서 설명 주석만 줄인 것이다(전체는 정답 풀이 파일). 원문 해설은 바깥 while을 "여정의 엔진"(큐에서 다음 장소를 꺼냄), 안쪽 for를 "사방 정찰"(네 방향을 보고 갈 곳을 큐에 적음)이라고 부른다. 왜 BFS인가 — 그리고 왜 값이 덮이지 않나 큐는 먼저 넣은 칸을 먼저 꺼내므로(FIFO) 거리 2인 칸을 모두 본 뒤에 거리 3인 칸을 본다. 그래서 어떤 칸에 처음 적힌 숫자가 그 칸의 최단 거리이고, 이미 숫자가 적힌 칸(> 1)은 다시 건드리지 않으니 나중에 더 먼 길로 온 큰 숫자가 덮어쓰지 못한다. 칸마다 한 번씩만 큐에 들어가 100 × 100이어도 1만 번이면 끝난다. 흔히 틀리는 곳 1. DFS(재귀)로 끝까지 가 보기 — 처음 도착한 길이 가장 짧다는 보장이 없어 모든 길을 비교해야 하고, 길의 수는 맵이 커지면 폭발적으로 늘어난다. 최단 거리는 BFS. 2. 범위 검사를 뒤에 — maps[nx][ny]를 먼저 읽으면 맵 밖에서 ArrayIndexOutOfBoundsException. 원문처럼 범위부터. 3. 방문 표시를 꺼낼 때 하기 — 큐에 넣을 때 표시해야 같은 칸이 여러 번 들어가지 않는다(이 풀이는 거리를 적는 순간이 곧 표시). 4. "지나는 칸 수"는 출발 칸 포함 — 출발 칸이 이미 1이라 이웃은 2부터. 예시 답 11은 칸 수다. 로컬에서 본 두 가지 (답에는 영향 없음 · 조건 밖) · 출발 칸은 값이 1이라 "처음 가는 길"로 보여, 이웃에서 한 번 3으로 덮인다(예시 1을 푼 뒤 출발 칸 = 3). 그 칸의 이웃은 이미 모두 적혀 있어 더 퍼지지 않는다. · 입력 배열에 직접 거리를 적으므로 호출한 쪽의 맵이 바뀐다. 원본이 필요하면 복사본이나 별도 dist 배열을 쓴다. · 도착 칸이 벽(0)인 맵은 문제에 나오지 않지만, 넣으면 answer == 1만 막아서 0이 나온다. answer <= 1 ? -1 : answer로 쓰면 둘 다 막힌다.

실행 결과큐를 쓰지 않는 다른 방법으로 구한 거리와 비교 먼저 예측 → 펼쳐서 확인 
공식 예제 → 11 · -1                                                     → 통과
무작위 3,000개 (1~12 × 1~12, 벽 0~45%, 도착 가능 1,812개)               → 다른 방법으로 구한 거리와 같음
한 줄짜리 맵 [[1,1,1,1,1]]                                              → 5   (n = 1 도 허용)
최대 크기 100 × 100 (벽 없음)                                           → 199, 이 PC에서 0.1ms
예시 1을 푼 뒤 맵                                                       → 도착 칸 11, 출발 칸 3
(조건 밖) 도착 칸이 벽 [[1,1],[1,0]]                                     → 0
기댓값은 큐를 쓰지 않는 코드예요 — 모든 칸을 되풀이해 훑으며 "이웃 거리 + 1이 더 작으면 바꾸기"를 더 바뀌는 것이 없을 때까지 반복(Bellman-Ford 방식, 시드 27 고정). 100 × 100의 시간은 앞의 3,000번으로 JIT가 데워진 뒤 한 번 잰 값이에요. 로컬 검증이며 프로그래머스 재채점은 아닙니다.
📌 주요 개념 정리

(1) 큐(Queue) — 먼저 넣은 것이 먼저 나온다(FIFO) add/offer로 뒤에 넣고 poll로 앞에서 꺼낸다. 좌표 두 개는 int[]{x, y}로 묶어 Queue<int[]>. 구현은 LinkedList나 ArrayDeque. → 기능개발(큐) · ArrayList vs LinkedList (2) 방향 벡터 dx · dy dx = {-1, 1, 0, 0}, dy = {0, 0, -1, 1}를 for (i = 0; i < 4; i++)로 돌리면 네 방향 좌표가 x + dx[i], y + dy[i]. 대각선까지면 8방향 배열. (3) 거리 기록과 방문 표시를 한 번에 별도 visited 없이 맵 자체에 maps[x][y] + 1을 적고, 1보다 큰 값은 "이미 간 곳"으로 본다. 코드는 짧지만 입력이 바뀐다는 점은 기억. (4) DFS와 BFS 모든 경우를 세는 문제(타겟 넘버)는 DFS도 좋지만, "가장 가까운 · 가장 짧은"은 BFS. 둘 다 "방문한 곳은 다시 가지 않는다"가 공통 규칙.

벽이 없는 3 × 4 맵이면 답은?
6. 오른쪽으로 3칸 · 아래로 2칸 = 5번 움직이고, 출발 칸까지 세면 6칸이에요. 벽이 없으면 (n − 1) + (m − 1) + 1 = n + m − 1 (100 × 100이면 199).
Queue 대신 Stack(나중에 넣은 것을 먼저)을 쓰면 무엇이 깨질까?
가까운 칸부터 본다는 순서가 깨져 깊이 우선처럼 움직여요. 어떤 칸에 먼 길로 먼저 도착해 큰 숫자가 적히면, 그 뒤 더 짧은 길이 와도 > 1 검사에 막혀 고쳐지지 않아 최단이 아닌 값이 답이 될 수 있어요(실행하지 않은 설명).
도착 칸 값이 끝까지 1이면 왜 "못 갔다"는 뜻일까?
도착 칸에 닿았다면 이웃 값 + 1이 적혀 2 이상이 됐을 거예요. 1 그대로라는 건 아무도 그 칸에 거리를 적지 않았다는 뜻이라 -1.

💼 이 유형을 다시 만나면미로 · 지도 · "최소 몇 번 만에"는 BFS가 기본이에요. 실무에서도 지하철 최소 환승, 소셜 그래프의 "몇 다리 건너 아는 사이", 웹 크롤러의 깊이 제한이 같은 구조예요. 파이썬(이번 주 과정)으로는 from collections import deque의 append · popleft가 자바의 add · poll에 해당해요.
