JAVA두 배열을 같은 인덱스로boolean 조건삼항 연산자

한 줄 요약절댓값 배열 absolutes와 부호 배열 signs를 같은 인덱스로 함께 돌면서, signs[i]가 true면 더하고 false면 뺀다.

쉽게 말하면금액이 적힌 종이와 "입금 / 출금" 도장이 찍힌 종이가 따로 있어요. 같은 줄끼리 맞춰 보면서 입금이면 더하고 출금이면 빼면 통장 잔액이 나옵니다.

정수들의 절댓값을 차례대로 담은 배열 absolutes와 각 정수의 부호를 담은 배열 signs가 주어진다. signs[i]가 true면 양수, false면 음수일 때 실제 정수들의 합을 반환하는 문제. 두 배열의 길이는 1 이상 1,000 이하로 같고, 절댓값은 1 이상 1,000 이하.

📄 제출 코드 파일 · 📁 24회차 전체 기록

JAVA 제출 코드 · 오답노트 원문 (PASS) 
class Solution {
    public int solution(int[] absolutes, boolean[] signs) {
        int answer = 0;

        for(int i=0;i<absolutes.length;i++){         // ← 두 배열을 같은 i 로 본다
            if(signs[i]==true){
                answer = answer + absolutes[i];
            } else if (signs[i] == false){              // ← 여기 오면 이미 false — 조건이 늘 참
                answer = answer - absolutes[i];
            }
        }

        return answer;
    }
}
💡 정답 풀이

제출 코드가 정답이다. 오답노트에는 정답 풀이·개념 정리 칸이 비어 있어, 아래는 이 문제에서 짚어 둘 점이다. 더 짧게 쓰는 법 1. signs[i] == true → signs[i] — boolean 값은 그 자체가 조건이다. == true를 붙여도 결과는 같지만 군더더기다. 2. else if (signs[i] == false) → else — 앞의 if가 거짓이면 signs[i]는 이미 false라 두 번째 조건은 항상 참이다. 3. 삼항 연산자로 한 줄 — answer += signs[i] ? absolutes[i] : -absolutes[i]; 흔히 틀리는 곳 1. 향상된 for문(for (int a : absolutes)) — 값만 꺼내고 인덱스가 없어 짝이 되는 signs[i]를 찾을 수 없다. 두 배열을 함께 볼 때는 인덱스 for문을 쓴다. 2. if (signs[i] = true) — = 하나는 대입이다. 값이 늘 true가 되어 전부 더해지는데, boolean 대입은 조건 자리에 들어가도 컴파일이 된다. ==를 아예 안 쓰는 1번 방식이 이 실수까지 막는다.

괄호가 ( ) { } [ ] 세 종류로 섞이면 정수 카운터로 충분할까?

제출 코드가 정답이다. 오답노트에는 정답 풀이·개념 정리 칸이 비어 있어, 아래는 이 문제에서 짚어 둘 점이다. '%강원도%'와 '강원도%' 주소는 시·도부터 적으니 "강원도에 위치한"은 '강원도'로 시작하는 주소다. 그래서 LIKE '강원도%'(앞부분 일치)가 뜻에 더 정확하다. '%강원도%'는 다른 도의 "…강원도로 12" 같은 주소까지 잡을 수 있다. 이번 제출('%강원도%')은 채점을 통과했다. 채점 데이터에 그런 주소가 있는지는 알 수 없다. 앞부분 일치에는 하나의 장점이 더 있다. 앞에 %가 붙으면 인덱스를 쓸 수 없다. 목차를 "가"부터 찾을 수는 있어도 "…원도"로 끝나는 말은 처음부터 다 읽어야 하는 것과 같다. 흔히 틀리는 곳 1. LIKE '강원도'(% 없음) — 와일드카드가 없으면 "주소 전체가 정확히 '강원도'"인지 비교하는 것과 같아 0행이다. 2. 정렬 방향 — DESC로 쓰면 순서가 뒤집혀 오답. 오름차순은 ASC이고 생략해도 오름차순이다.

📌 주요 개념 정리

(1) LIKE의 와일드카드 %는 0글자 이상 아무 글자, _는 정확히 한 글자. '강원도%' 앞부분 · '%강원도' 뒷부분 · '%강원도%' 어디든. → 🗄️ 09. LIKE와 와일드카드 · 자동차 종류 별 특정 옵션이 포함된 자동차 수 구하기 (2) 앞에 %가 붙으면 인덱스를 못 쓴다 → 인덱스 개념 (3) ORDER BY의 기본은 오름차순 ASC는 생략해도 된다. 여러 기준이면 쉼표로 이어 기준마다 방향을 정한다. → 🗄️ 15. ORDER BY

답을 펼치기 전에 머릿속으로 먼저 대답해 보세요. 오답노트는 다시 떠올려 봐야 내 것이 됩니다.

LIKE '강원_' 는 '강원도 정선군 …' 주소를 찾을까?
찾지 못합니다. _는 정확히 한 글자라서 "강원" 뒤에 딱 한 글자로 끝나는 값(예: "강원도")만 맞아요. 뒤에 무엇이든 오게 하려면 '강원%'입니다.
'%강원도%' 와 '강원도%' 중 ADDRESS 인덱스를 쓸 수 있는 것은?
'강원도%'입니다. 시작 글자가 정해져 있어 정렬된 인덱스에서 "강원도…"가 모인 곳으로 바로 갈 수 있어요. 앞에 %가 붙으면 시작 글자를 몰라 처음부터 끝까지 다 봐야 합니다.

💼 이 유형을 다시 만나면검색 기능의 기본이 LIKE입니다. 실무에서 '%키워드%'는 큰 테이블에서 느려지기 쉬워, 시작 글자 검색으로 바꾸거나 전문 검색(MySQL FULLTEXT, 검색 엔진)을 씁니다. 코딩테스트에서는 문장이 말하는 범위("~로 시작하는", "~를 포함하는")에 맞춰 % 위치를 고르세요.

SQL 정답 풀이 (오답노트 원문 · 제출 코드는 남아 있지 않음) 
SELECT MONTH(START_DATE) AS MONTH, CAR_ID, COUNT(*) AS RECORDS
FROM CAR_RENTAL_COMPANY_RENTAL_HISTORY
WHERE START_DATE BETWEEN '2022-08-01' AND '2022-10-31'       -- ← ② 세는 쪽도 기간 안만
  AND CAR_ID IN (
      SELECT CAR_ID
      FROM CAR_RENTAL_COMPANY_RENTAL_HISTORY
      WHERE START_DATE BETWEEN '2022-08-01' AND '2022-10-31'   -- ← ① 고르는 쪽도 기간 안만
      GROUP BY CAR_ID
      HAVING COUNT(*) >= 5                                    -- ← 석 달 합계 5번 이상인 차
  )
GROUP BY MONTH(START_DATE), CAR_ID                             -- ← 월 + 차 두 기준으로 묶기
ORDER BY MONTH ASC, CAR_ID DESC;
💡 정답 풀이

제출 코드 칸이 비어 있어 실제로 어디서 틀렸는지는 알 수 없다. 아래는 이 문제에서 흔히 틀리는 곳(모두 실제로 돌려 봄)과 정답 풀이의 흐름이다. 흔히 틀리는 곳 1. 바깥 쿼리의 기간 조건을 뺀다 — 고른 차의 7월 · 11월 이력까지 월별로 세어진다. 서브쿼리에서 걸렀다고 끝이 아니다. 2. 서브쿼리의 기간 조건을 뺀다 — 기간 밖 이력으로 5번을 채운 차가 대상에 끼어든다(실행 결과의 2번 차: 기간 안 4번 + 7월 2번). 3. 서브쿼리 없이 월별로 묶고 HAVING COUNT(*) >= 5 — 조건이 "석 달 합계 5번"이 아니라 "한 달에 5번"으로 바뀐다. 4. 정렬 — 월은 오름차순, 같은 달 안에서는 자동차 ID 내림차순이다. 풀이 흐름 1. 서브쿼리: 기간 안 이력만 남겨 GROUP BY CAR_ID → HAVING COUNT(*) >= 5로 대상 차의 ID 목록. 2. 바깥 쿼리: 기간 안 이력 중 그 목록에 있는 차만 → GROUP BY MONTH(START_DATE), CAR_ID로 월·차별 COUNT(*). 3. 대여가 0번인 달은 처리할 필요가 없다. GROUP BY는 있는 행만 묶어서, 이력이 없는 달은 줄이 생기지 않는다.

(1) 집계 단위가 다르면 서브쿼리로 나눈다 고르는 기준(석 달 합계)과 결과 단위(월별 · 차별)가 다르면 한 번의 GROUP BY로 안 된다. "서브쿼리로 대상 ID 목록 줄이기 → 바깥 쿼리에서 세부 단위로 집계"가 정형화된 풀이다. → 🗄️ 13. 다중행 서브쿼리 — IN · ANY · ALL · 🗄️ 18. GROUP BY · 🗄️ 19. 🤔 스스로 확인

서브쿼리의 HAVING COUNT(*) >= 5 를 WHERE COUNT(*) >= 5 로 쓰면?

START_DATE 가 DATE 가 아니라 DATETIME 이고 10/31 오후에 시작한 대여가 있다면 BETWEEN '2022-08-01' AND '2022-10-31' 은 그 줄을 셀까?
세지 않습니다. '2022-10-31'은 10월 31일 0시 0분 0초로 해석돼서 그날 오후는 범위 밖이에요. 그럴 땐 START_DATE >= '2022-08-01' AND START_DATE < '2022-11-01'처럼 "다음 날 미만"으로 씁니다. 이 문제는 DATE라 해당하지 않아요.

💼 이 유형을 다시 만나면"기간 안에 N번 이상인 회원의 월별 추이" 같은 리포트는 실무 대시보드에서 아주 흔한 모양입니다. 서브쿼리가 길어지면 WITH(CTE)로 대상 목록에 이름을 붙여 읽기 쉽게 만들어요(→ 🗄️ 26. CTE (WITH)). 그리고 이 유형에서 가장 먼저 확인할 곳은 기간 조건을 두 곳 모두 걸었는지입니다.
