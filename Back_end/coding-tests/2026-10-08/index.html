JAVA 정답 풀이 (오답노트 원문 · 제출 코드는 남아 있지 않음) 
class Solution {
    public int solution(int num) {
        if (num == 1) return 0;                 // ← 처음부터 1이면 0

        long n = num;                           // ← int 오버플로 방지: long 으로 계산
        int count = 0;

        while (n != 1) {
            if (count == 500) return -1;        // ← 501번째 작업을 하기 전에 끊는다

            if (n % 2 == 0) {
                n /= 2;                         // ← 짝수
            } else {
                n = n * 3 + 1;                  // ← 홀수: 여기서 값이 크게 뛴다
            }
            count++;
        }
        return count;                           // ← 정확히 500번째에 1이 되면 500
    }
}

같은 숫자는 싫어

JAVA스택 Stack단락 평가연속 중복 제거Integer 비교

한 줄 요약배열을 앞에서부터 보며 바로 앞에 넣은 값과 다를 때만 넣는다. 정답 풀이는 스택을 쓰고 stack.isEmpty() || stack.peek() != arr[i]로 빈 스택에서 peek()을 부르지 않게 막는다. 결과는 stack.get(i)로 바닥부터 꺼내 원래 순서를 지킨다.

쉽게 말하면줄 서서 들어오는 사람을 명단에 적는데, 방금 적은 사람과 같은 사람이면 안 적는 거예요. 명단 맨 끝만 보면 되니까 스택(맨 위만 보는 상자)이 잘 맞고, 사실 "바로 앞 칸과 비교"만 해도 됩니다.

📄 정답 풀이 파일 · 📁 23회차 전체 기록

JAVA 정답 풀이 (오답노트 원문 · 제출 코드는 남아 있지 않음) 
import java.util.*;

public class Solution {
    public int[] solution(int []arr) {
        Stack<Integer> stack = new Stack<>();

        for (int i = 0; i < arr.length; i++) {
            if (stack.isEmpty() || stack.peek() != arr[i]) {   // ← 비었으면 peek 을 안 부른다
                stack.push(arr[i]);
            }
            else if (!stack.isEmpty() && arr[i - 1] == arr[i]) {  // ← 지워도 결과가 같은 블록
                stack.pop();
                stack.push(arr[i]);
            }
        }

        int[] ans = new int[stack.size()];
        for (int i = 0; i < ans.length; i++) {
            ans[i] = stack.get(i);                              // ← get(0) 이 바닥 = 처음 넣은 값
        }
        return ans;
    }
}
💡 정답 풀이

제출 코드 칸이 비어 있어 실제로 어디서 틀렸는지는 알 수 없다. 아래는 이 문제에서 흔히 틀리는 곳과 정답 풀이의 흐름이다. 흔히 틀리는 곳 1. 전체 중복 제거로 착각 — HashSet이나 distinct()를 쓰면 떨어져 있는 같은 숫자까지 지워 [1,3,0]이 된다. 문제는 연속된 것만 하나로. 2. 빈 스택에서 peek() — 조건 순서를 stack.peek() != arr[i] || stack.isEmpty()로 바꾸면 첫 원소에서 EmptyStackException. ||는 앞이 참이면 뒤를 보지 않는다(단락 평가). 3. 스택을 pop()으로 꺼내 배열에 담기 — 맨 위부터 나와서 순서가 거꾸로 된다. Stack은 Vector를 물려받아 get(0)이 맨 아래라 순서대로 옮길 수 있다. 4. Integer끼리 != — 정답 풀이는 peek()(Integer)과 arr[i](int)를 비교해서 Integer가 숫자로 풀려 값 비교가 된다. 둘 다 Integer면 주소 비교라 −128~127 밖의 같은 값이 "다르다"로 나온다(이 문제는 0~9라 드러나지 않음). 더 짧게 쓰는 방법 i == 0 || arr[i] != arr[i-1]이면 ArrayList에 넣기 — 스택 없이 "바로 앞 칸과 비교"만으로 같은 결과다. 정답 풀이의 else if 블록은 같은 값을 꺼냈다 다시 넣을 뿐이라 지워도 된다(원문 주석도 같은 말).

실행 결과무작위 배열과 Integer 비교 먼저 예측 → 펼쳐서 확인 
공식 예제 [1,1,3,3,0,1,1] → [1,3,0,1], [4,4,4,3,3] → [4,3]   → 통과
무작위 20,000개 (길이 1~200, 0~9)                            → 모두 통과 ("바로 앞 칸과 비교" 코드와 같은 결과)
길이 1,000,000 (세 개씩 같은 수)                             → 결과 333,334개, 약 10ms
Integer 끼리: peek() != Integer 1000                         → true   (같은 값인데 "다르다")
Integer 와 int: peek() != 1000                               → false
peek().equals(Integer 1000)                                  → true
Integer는 −128~127만 미리 만들어 둔 객체를 함께 쓰고, 그 밖의 값은 상자를 새로 만듭니다. 그래서 1000짜리 상자 두 개를 !=로 비교하면 서로 다른 상자라 true예요. 한쪽이 int면 상자를 풀어 값으로 비교합니다. 로컬 검증이며 프로그래머스 재채점은 아닙니다.

순서를 지키는 LinkedHashSet이라도 [1,3,0]이 됩니다. 마지막 1은 앞의 1들과 떨어져 있어서 남아야 하는데, Set은 "이미 본 값"을 전부 지우기 때문이에요.
조건을 stack.peek() != arr[i] || stack.isEmpty() 로 순서만 바꾸면?
첫 원소에서 스택이 비어 있는데 peek()을 먼저 불러 EmptyStackException이 납니다. ||는 왼쪽부터 보므로 "비었는지"를 먼저 물어야 해요.
스택을 쓰지 않고 이 문제를 푸는 가장 간단한 조건은?
i == 0 || arr[i] != arr[i - 1]이면 결과 목록에 넣습니다. 첫 칸은 비교할 앞 칸이 없으니 무조건 넣고, 나머지는 바로 앞 칸과 다를 때만. 두 값 모두 int라 Integer 비교 함정도 없어요.

쉽게 말하면NULL은 "0살"이 아니라 "모름"이에요. "모름과 같은가?"라고 물으면 답도 "모름"이라 아무도 뽑히지 않죠. 그래서 "모름인가?"를 묻는 전용 말 IS NULL을 씁니다. 그리고 셀 때는 나이 칸이 아니라 사람 수(행)를 세야 해요.

from USER_INFO
where AGE is NULL;              -- ← = NULL 이 아니라 IS NULL
💡 정답 풀이

제출 코드가 정답이다. 오답노트에는 정답 풀이·개념 정리 칸이 비어 있어, 아래는 이 문제에서 짚어 둘 점이다. 흔히 틀리는 곳 1. WHERE AGE = NULL — NULL과의 비교는 참도 거짓도 아닌 UNKNOWN이라 어떤 행도 남지 않아 0이 나온다. 2. COUNT(AGE) — 컬럼을 세는 COUNT는 NULL을 건너뛴다. 나이가 NULL인 행만 남겨 놓고 나이를 세니 0. 3. AGE = 0과 혼동 — 0살은 값이 있는 것이다. NULL과 다르다. 같은 답을 다르게 SELECT COUNT(*) - COUNT(AGE) AS USERS FROM USER_INFO; — 전체 행 수에서 나이가 있는 행 수를 빼면 NULL의 개수다.

🤔 스스로 확인

답을 펼치기 전에 머릿속으로 먼저 대답해 보세요. 오답노트는 다시 떠올려 봐야 내 것이 됩니다.

나이 26 · NULL · NULL · 0 · 31 인 5명에서 AVG(AGE)는 얼마일까?
NULL 두 명은 빼고 (26 + 0 + 31) / 3 = 19입니다. 5로 나누지 않아요. NULL을 0으로 보고 싶으면 AVG(IFNULL(AGE, 0))(MySQL)처럼 바꿔 줘야 합니다.
"나이 정보가 있는 회원 수"를 WHERE 없이 한 줄로 구하려면?
SELECT COUNT(AGE) FROM USER_INFO; — 컬럼을 세는 COUNT는 NULL을 건너뛰니 그 자체가 "값이 있는 행 수"예요.

💼 이 유형을 다시 만나면실무 데이터에는 "입력 안 함(NULL)"이 늘 섞여 있어서, 통계·리포트 쿼리에서 = NULL, COUNT(컬럼), AVG 분모 실수가 숫자를 조용히 틀리게 만듭니다. "비어 있는 데이터가 몇 건인가"를 먼저 세어 보는 습관(COUNT(*) - COUNT(컬럼))이 데이터 품질 점검의 첫걸음이에요.

SELECT
    CAR_ID,
    CASE
        WHEN MAX(CASE WHEN '2022-10-16' BETWEEN START_DATE AND END_DATE THEN 1 ELSE 0 END) = 1
                                                -- ← 이력마다 1/0 깃발, 차마다 가장 큰 값

        ELSE '대여 가능'
    END AS AVAILABILITY
FROM CAR_RENTAL_COMPANY_RENTAL_HISTORY
GROUP BY CAR_ID                                 -- ← 차 한 대 = 한 줄
ORDER BY CAR_ID DESC;

MAX 대신 MIN(CASE … THEN 1 ELSE 0 END) = 1 로 쓰면 무슨 뜻이 될까?
"그 차의 모든 이력이 10/16을 포함한다"가 됩니다. 이력이 하나라도 10/16과 겹치지 않으면 0이 섞여 MIN이 0이 되니까요. MAX = 1은 "하나라도", MIN = 1은 "전부"예요.
END_DATE가 '2022-10-16 18:00:00' 같은 DATETIME이면 BETWEEN '2022-10-16' AND … 의 반대 방향 조건에서 무엇을 조심해야 할까?
'2022-10-16'은 그날 0시로 해석됩니다. 예를 들어 START_DATE BETWEEN '2022-10-01' AND '2022-10-16'이면 16일 0시 이후에 시작한 기록이 빠져요. 하루 전체를 넣으려면 START_DATE < '2022-10-17'처럼 다음 날 미만으로 씁니다. 이 문제의 컬럼은 DATE라 상관없어요.
대여 기록이 한 번도 없는 차도 '대여 가능'으로 보여 주려면 무엇이 더 필요할까?
이력 테이블에는 그 차가 아예 없으니, 자동차 목록 테이블(CAR_RENTAL_COMPANY_CAR)을 기준으로 이력을 LEFT JOIN해야 합니다. 이 문제는 이력 테이블만 보라고 했으니 필요 없어요.

💼 이 유형을 다시 만나면"회원별 이번 달 구매 여부", "상품별 품절 이력 존재 여부", "직원별 결근 기록 유무"처럼 이력 테이블에서 엔티티별 상태 하나를 뽑는 쿼리는 실무 리포트의 단골입니다. 먼저 "결과 한 줄 = 무엇 하나인가"를 정하고 그것으로 GROUP BY, 상태는 MAX/SUM(CASE …)로 판정하는 순서를 기억하세요.
