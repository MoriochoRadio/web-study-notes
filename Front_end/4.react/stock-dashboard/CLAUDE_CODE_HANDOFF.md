# 🧭 Claude Code 인수인계 문서 (CLAUDE_CODE_HANDOFF.md)

> 이 문서는 다른 AI 세션(Cowork)에서 진행하던 작업을 **Claude Code**로 이어받아
> UI/UX를 전면 개편하기 위해 작성되었습니다. Claude Code는 아래 내용을 먼저 정독한
> 뒤 작업을 시작하세요. 특히 "② 절대 규칙" 섹션은 어떤 지시를 받아도 우선합니다.

## ① 프로젝트가 뭔가

**StockDash** — Finnhub API + WebSocket 기반 실시간 미국 주식 대시보드.
코딩 취업 아카데미의 React 풀스택 캡스톤 과제이며, 정식 명세는 저장소 상위 폴더의
`React풀스택웹서비스개발프로젝트기능정의서및제출가이드.docx`에 있습니다.

과제의 핵심 채점 기준(문서 원문, 문단 59): "본 과제는 AI(Gemini, ChatGPT 등)를 자유롭게
활용할 수 있습니다. 단, **'AI가 대신 만들어준 코드'가 아닌 '내가 이해하고 제어한 코드'**
임을 증명해야 하며, 이를 위해 3가지 제출 문서(`PROMPT_LOG.md`, `CODE_REVIEW.md`,
`README.md`)를 반드시 작성해야 합니다." — 특정 AI 도구로 제한하지 않으므로 Claude Code
사용도 문제없습니다.

기능 요구사항 8개(스마트 검색, 실시간 시세, 전광판, 인터랙티브 차트, 전문가 투자의견,
어닝 서프라이즈, 뉴스 피드, 관심 종목 관리)는 **모두 구현·검증 완료**된 상태이며,
기능정의서 전체를 재추출해 만든 체크리스트로 재감사까지 마쳤습니다. 현재 세 문서
(`README.md`, `PROMPT_LOG.md`, `CODE_REVIEW.md`)에는 이 과정 전체가 사례별로 기록되어
있습니다 — Claude Code는 작업 전에 이 세 파일을 먼저 읽어서 지금까지의 맥락(어떤 실수를
했고 어떻게 고쳤는지, 어떤 부분이 AI 중심/본인 직접 구현인지)을 파악하세요.

## ② 절대 규칙 — 반드시 지킬 것

기능정의서 제출 가이드 문단 80~81이 AI 활용 범위를 명확히 나누고 있습니다:

> **[AI 중심 구현]** UI 스타일링(Tailwind CSS), 단순 반환 템플릿 코드 등
> **[본인 직접 구현/리팩토링]** Zustand 스토어 상태 로직, Custom Hook 연동,
> 비동기 데이터 에러 핸들링 등

이번 라운드의 목표는 **"기능서에서 AI 활용이 허용된 부분만, 전면적으로" 개선**하는 것이지,
이미 본인이 직접 짜고 검증한 로직을 새로 짜는 게 아닙니다. 아래 표를 기준으로 움직이세요.

### 🟢 자유롭게 전면 개편해도 되는 영역 (AI 중심 구현 허용)

- 모든 컴포넌트의 **Tailwind className** — 색상, 여백, 타이포그래피, 그림자, 반응형
  breakpoint, 애니메이션, 다크모드 variant 전부 자유롭게 다시 디자인 가능.
- **JSX 레이아웃 마크업** — 카드 배치 순서, 그리드 구조, 섹션 구분, 아이콘/시각적 장식
  추가. 단, `{data.xxx}` 같은 실제 데이터 바인딩 표현식 자체는 건드리지 않기(아래 참고).
- `src/app/globals.css` — 색상 팔레트(`@theme` 블록), 커스텀 애니메이션(`@keyframes`)
  확장/추가는 자유.
- `src/components/Skeleton.jsx` — 순수 로딩 UI라 자유 개편.
- `src/app/layout.js`의 헤더 디자인, `ThemeToggle.jsx`/`ThemeWrapper.jsx`의 **UI**(버튼
  모양, 아이콘, 위치 등 — `toggleTheme` 로직 자체는 스토어에 있으니 그대로 재사용).
- 새로운 순수 프레젠테이션(디자인만 담당하는) 컴포넌트를 추가하는 것도 허용.

### 🔴 절대 새로 만들거나 고치면 안 되는 영역 (본인 직접 구현 — 보존 필수)

아래 파일들의 **로직 부분**(상태 관리, `useEffect` 의존성 배열과 cleanup, fetch 체이닝,
조건부 분기, WebSocket 구독/해제)은 본인이 직접 짜고 디버깅까지 마친 핵심 평가 대상입니다.
UI 스타일링을 입히는 것은 괜찮지만, **로직 자체를 재작성하거나 "개선"이라는 이름으로
갈아엎지 마세요**:

- `src/store/useWatchlistStore.js` — `addSymbol`/`removeSymbol`/`isWatched`/`toggleTheme`
  액션 함수 바디
- `src/hooks/useDebounce.js`, `useStockData.js`, `useLiveTicker.js` — 전체 로직
- `src/lib/market.js` — 전체 로직
- `src/app/api/**/route.js` (search, quote, recommendation, earnings, news/market,
  news/company, stock/[symbol]/chart) — fetch 순서, 에러 처리, `Response.json()`
  응답 shape. **응답 shape을 바꾸면 이걸 쓰는 컴포넌트가 전부 깨집니다.**
- 각 컴포넌트 안의 `useState`/`useEffect`/`fetch().then().catch()` 로직, 조건부 `return`
  가드(`if (!symbol) return null` 등)의 **순서와 존재 여부** — 이건 이미 Hooks 규칙
  위반을 2번 겪고 고친 부분이라 위치를 다시 흐트러뜨리면 같은 버그가 재발합니다.

**판단 기준이 애매하면**: "이 코드를 지워도 화면에 뭐가 보이는지만 바뀌는가(데이터는
그대로 처리됨) → 개편 가능" / "이 코드를 지우면 데이터를 가져오거나 상태를 바꾸는 방식
자체가 바뀌는가 → 손대지 말 것".

## ③ 지금까지 진행 상황 요약

| 기능 | 상태 | 비고 |
| --- | --- | --- |
| 0~8. 전체 기능 8종 | ✅ 완료 | 브라우저 실측 테스트로 최종 검증 완료 |
| UX 필수 요구사항 (스켈레톤, 반응형 그리드) | ✅ 완료 | |
| 전광판 흐르는 애니메이션 | ✅ 완료 | `globals.css`의 `ticker-scroll` keyframe |
| 다크모드 토글 | ✅ 완료 | `useWatchlistStore.js`의 `theme` 슬라이스 + `ThemeWrapper` |
| 선택 종목 강조 표시 | ✅ 완료 | `TickerBoard`/`WatchlistPanel` 동시 하이라이트 |
| 기능정의서 전체 요구사항 재감사 | ✅ 완료 | 문서 전체 재추출로 교차 검증 |
| 제출 문서 3종 (README/PROMPT_LOG/CODE_REVIEW) | ✅ 최신 상태 | 사례 1~13까지 기록됨 |

즉, **기능 구현 관점에서는 더 할 일이 없고**, 이번에 하려는 건 순수하게 위 ②의 허용
범위 안에서 **비주얼 완성도를 한 단계 더 끌어올리는 것**입니다.

## ④ 이번 라운드에서 하고 싶은 것

기능서에 없는 부분까지 포함해서, "AI를 잘 활용해서 UI를 개선했다"는 것을 보여줄 수
있을 정도로 전면적인 비주얼 개편을 원함. 예를 들어 (강제 아님, 아이디어 예시):

- 카드 컴포넌트들의 시각적 위계(제목/숫자/보조정보 크기·색 대비) 재정비
- 로딩 스켈레톤을 실제 카드 레이아웃과 더 비슷한 모양으로 고도화
- 차트/막대그래프 색상·범례·툴팁 디자인 다듬기
- 반응형 브레이크포인트를 `md` 하나가 아니라 `sm`/`lg`까지 세분화
- 마이크로 인터랙션(hover, transition, focus ring 등) 보강
- 전체적인 타이포그래피/스페이싱 스케일 통일

## ⑤ Claude Code의 Skills 활용

Claude Code에 프론트엔드 디자인/UI 폴리싱 관련 Skill이 설치되어 있다면 이번 작업에
적극 활용하세요 (사용자가 "Skills를 써서 이걸 보여주고 싶다"고 명시적으로 요청함).
작업 시작 전에:

1. Claude Code에게 현재 설치된 Skill 목록을 먼저 물어보고, 그중 UI/디자인/접근성/
   프론트엔드 코드리뷰와 관련된 것이 있으면 이번 작업에 사용할 것.
2. 스크린샷 비교나 브라우저 자동 확인이 가능한 Skill/도구(예: Playwright 기반 도구)가
   있다면, 개편 전/후 화면을 실제로 캡처해서 비교하는 데 사용 — 이 결과물은 그 자체로
   "AI를 활용해 검증까지 했다"는 증거가 되므로 `CODE_REVIEW.md`에 캡처 근거와 함께
   기록하면 좋음.
3. 특정 Skill이 없다면 억지로 찾지 말고, 없다고 솔직히 말한 뒤 일반적인 Tailwind/React
   베스트 프랙티스로 진행.

## ⑥ 작업 후 문서화 (가장 중요)

이 프로젝트의 대전제는 "AI가 대신 만든 코드가 아니라 내가 이해하고 통제한 코드"임을
증명하는 것입니다. UI 개편이 끝나면 반드시 아래를 갱신하세요:

1. **`PROMPT_LOG.md`**: 사례 13 뒤에 **사례 14**로 이어서, 이번에 어떤 지시를 내렸고
   (이 핸드오프 문서 자체가 최초 프롬프트 역할), AI가 어떤 선택을 했는지, 왜 그
   디자인을 골랐는지 기록.
2. **`CODE_REVIEW.md`**: 실제로 바뀐 컴포넌트별로 Before/After 코드 조각과 "왜 이렇게
   바꿨는지"를 기록. 로직은 그대로고 스타일만 바뀐 걸 명확히 보여줄 것(같은 `useEffect`/
   `fetch` 블록이 Before/After에 동일하게 남아있어야 함).
3. **`README.md`**의 "기여도 및 핵심 코드 명세서" 섹션 — "AI 중심 구현" 목록에 이번
   개편으로 바뀐 파일들을 추가. (이미 다크모드 토글/선택 강조 항목이 있으니 그 아래에
   이어서 적으면 됨.)
4. 가능하면 실제로 `npm run dev`를 띄워서 브라우저로 눈으로 확인 — 특히 데이터가 없는
   상태(스켈레톤), 에러 상태, 라이트/다크 모드, 모바일 폭에서 각각 확인.

## ⑦ Claude Code에 실제로 줄 프롬프트 예시

아래 그대로 복사해서 Claude Code에 붙여넣어도 되고, 상황에 맞게 문구만 바꿔도 됩니다.

**최초 오리엔테이션 프롬프트** (작업 시작 시 1회):
```
이 폴더의 CLAUDE_CODE_HANDOFF.md를 먼저 전부 읽어줘. 그 문서에 나온 "절대 규칙"
(어떤 파일/로직은 건드리면 안 되고, 어떤 부분만 자유롭게 개편해도 되는지)을 스스로
요약해서 나한테 다시 말해줘. 이해한 게 맞는지 내가 확인한 다음에 실제 작업을
시작하자. 먼저 설치된 Skill 목록도 보여줘 — UI/디자인/프론트엔드 관련 Skill이
있으면 이번 작업에 쓰고 싶어.
```

**개편 지시 프롬프트** (오리엔테이션 확인 후):
```
좋아, 이해한 그대로 진행해줘. CLAUDE_CODE_HANDOFF.md의 "🟢 자유롭게 전면 개편해도
되는 영역"에 있는 것들만 대상으로, "④ 이번 라운드에서 하고 싶은 것"에 나온 방향
(시각적 위계 정리, 스켈레톤 고도화, 차트 디자인, 반응형 세분화, 마이크로 인터랙션,
타이포그래피 통일)으로 전면적으로 개선해줘. 컴포넌트 하나씩 순서대로 진행하면서,
바꾸기 전에 어떤 부분을 왜 바꾸는지 나한테 먼저 짧게 설명하고 진행해줘. "🔴 절대
건드리면 안 되는 영역"에 있는 로직(useEffect, fetch, 상태 관리, API route 응답
shape)은 그대로 두고, className과 JSX 마크업 구조만 바꿔야 해.
```

**중간 점검 프롬프트** (컴포넌트 몇 개 끝난 뒤):
```
지금까지 바꾼 컴포넌트들, 로직(fetch/useEffect/상태 관리) 쪽은 정말 하나도 안
건드렸는지 diff 기준으로 다시 한번 검증해줘. 문제없으면 npm run dev로 띄워서
브라우저로 직접 확인해보고 스크린샷 보여줘.
```

**마무리 문서화 프롬프트** (개편 다 끝난 뒤):
```
UI 개편이 다 끝났어. CLAUDE_CODE_HANDOFF.md의 "⑥ 작업 후 문서화" 순서대로
PROMPT_LOG.md에 사례 14, CODE_REVIEW.md에 이번 개편의 Before/After, README.md
기여도 지표를 갱신해줘. 로직은 그대로고 스타일만 바뀐 게 CODE_REVIEW.md 안에서
명확히 드러나게 해줘.
```
