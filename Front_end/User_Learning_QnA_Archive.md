## 🎨 세션 1: Tailwind CSS v4 & 다크모드 DOM 조작

### Q1. `Unknown at rule @variant` 식별 에러가 왜 나오나요?
* **사용자 질문**: `globals.css` 7번째 줄에 `@variant` 부분에 빨간 밑줄 에러가 떠요.
* **원인 및 답**: `@variant`는 **Tailwind CSS v4**에서 클래스 기반 다크모드를 정의하는 **정식 문법**입니다. 다만 VS Code 기본 CSS Linter가 Tailwind v4의 신규 지시어를 인식하지 못해 발생한 단순 에러 표출입니다. (Next.js 실제 빌드는 정상)
* **해결**: `.vscode/settings.json`에 `"css.lint.unknownAtRules": "ignore"`를 추가하여 에디터 경고를 제거했습니다.

---

### Q2. `ThemeWrapper`에서 `.dark` 클래스를 추가하면 알아서 싹 다 다크모드로 변경되나요?
* **사용자 질문**: 지금 내가 보고 있는 곳에서 다크 클래스를 추가하면 알아서 싹 다 추가되는 거야?
* **답**: **네, 싹 다 바뀝니다!**
  `ThemeWrapper`가 `document.documentElement`(`<html>` 태그)에 `dark` 클래스를 붙이면, `globals.css`에 선언된 `@variant dark (&:where(.dark, .dark *));` 규칙에 따라 웹 페이지 내부의 모든 컴포넌트 중 `dark:bg-...`, `dark:text-...` 스타일을 가진 요소들이 일괄 활성화됩니다.

---

### Q3. `ThemeWrapper` 함수는 어디에서 쓰이고 무슨 역할을 하나요?
* **사용자 질문**: 아직 어디에 저 함수가 쓰이는지는 모르는 거지? 그냥 일단 html 칠드런이 들어오면 그 theme에 다크를 추가한다 이런 건가?
* **답**: `ThemeWrapper`는 최상위 레이아웃 파일인 `src/app/layout.js`에서 전체 앱을 감싸는 형태로 사용됩니다.
  * 자식 요소들(`children`)은 화면에 그대로 출력하고,
  * 내부 `useEffect`를 통해 전역 스토어의 `theme` 값('dark' 또는 'light')에 따라 최상단 `<html>` 태그의 클래스를 스위치처럼 온/오프하는 역할을 합니다.

---

### Q4. `layout.js`에 `dark:bg-...` 스타일이 이미 적혀있는데 왜 평소에는 적용이 안 되나요?
* **사용자 질문**: 여기에 다 dark가 여러 곳에 붙어있는데 어디에 적용되는 거야? 저 다크들은 이미 있는 거 아니야?
* **답**: `dark:`는 스위치가 켜져야만 동작하는 **"다크모드 전용 예약 조건"**입니다.
  * ☀️ **라이트 모드 (`<html>`)**: `dark:` 가 안 붙은 일반 클래스만 적용 (예: `bg-white`)
  * 🌙 **다크 모드 (`<html class="dark">`)**: `dark:` 가 붙은 클래스가 일반 클래스를 덮어씀 (예: `dark:bg-stock-bg`)

---

### Q5. `<ThemeWrapper>` 아래만 다크모드가 적용되는 것 아닌가요? 감싸지 않은 `<body>`는 왜 바뀌죠?
* **사용자 질문**: 그럼 layout에서 `<ThemeWrapper>` 밑의 부분만 적용돼? 왜지?? 원래는 저렇게 감싸두면 아래만 되는 거 아니야?
* **답**: 일반적인 리액트 JSX 구조에서는 감싸진 하위 요소만 영향을 받는 것이 맞습니다. **하지만 `ThemeWrapper` 내부 코드는 자바스크립트 브라우저 객체인 `document.documentElement`(`<html>` 태그)를 직접 선택해서 클래스를 변경**합니다.
  `<body>` 태그도 결국 `<html>` 태그의 자식이므로, JSX 감싸기 위치와 관계없이 **페이지 최상단부터 전체가 다크모드로 변경**됩니다.

## ⚡ 세션 2: Next.js 서버/클라이언트 컴포넌트 & 환경변수

### Q6. 왜 웹소켓이나 API 키를 가져올 때 `NEXT_PUBLIC_` 키를 써야 하나요?
* **사용자 질문**: 클라이언트에서 가져와야 한다는 게 무슨 소리야?
* **답**: 
  * Next.js에서 일반 환경변수(`FINNHUB_API_KEY`)는 **서버 측(API route, Server Component)**에서만 접근 가능합니다.
  * 브라우저 클라이언트 컴포넌트(`'use client'`)에서 직접 웹소켓(`wss://`)이나 API를 연결하려면 변수명 앞에 **`NEXT_PUBLIC_`** 이 붙어있어야만 Next.js가 브라우저 번들 파일에 이 값을 포함시켜 줍니다.

## 📈 세션 3: Recharts 차트, 배열 조작 & WebSocket 실시간 통신

### Q7. `setChartData((prev) => [...prev.slice(-59), point])`에서 `-59`는 어떻게 작용하나요?
* **사용자 질문**: `setChartData((prev) => [...prev.slice(-59), point])` 이게 뭐야? -59가 어떻게 작용돼?
* **답**: **슬라이딩 윈도우 (Sliding Window)** 기법입니다.
  1. `prev.slice(-59)`: 기존 배열에서 가장 최근 **뒤쪽 59개**만 남기고, 가장 오래된 맨 앞 1개를 버립니다.
  2. `[...prev.slice(-59), point]`: 59개 뒤에 새 시세 데이터 점(`point`) 1개를 덧붙입니다.
  3. 결과적으로 차트의 데이터 개수가 무한히 늘어나 렉이 걸리는 것을 막고 **항상 최신 60개로 일정하게 유지**됩니다.

---

### Q8. 웹소켓(WebSocket)이 무엇인가요?
* **사용자 질문**: 웹소켓이 뭐야?
* **답**: 
  * **일반 HTTP 통신**: 손님이 주문(Request)할 때만 사장님이 대답(Response)하고 연결이 끊어지는 일회성 주문 방식.
  * **웹소켓 통신 (`wss://`)**: 손님과 사장님이 1:1 전용 전화선을 계속 켜놓고(양방향 연결), 서버에 새 데이터가 생길 때마다 0.001초 만에 브라우저로 직접 쏴주는 실시간 통신 방식입니다.

---

### Q9. `pushPrice(msg.data[msg.data.length - 1].p)`에서 `.p`는 무슨 문법인가요?
* **사용자 질문**: `pushPrice(msg.data[msg.data.length - 1].p)` 여기에서 `.p`는 뭐야? 뭔 문법이지?
* **답**: 특별한 자바스크립트 문법이 아니라, **Finnhub 웹소켓 API가 보내주는 응답 데이터 객체의 속성(Property) 이름**입니다.
  * Finnhub 웹소켓 응답 형식: `{ type: 'trade', data: [{ s: 'AAPL', p: 182.5, v: 100 }] }`
  * `msg.data[msg.data.length - 1]`로 가장 최신 체결 거래 객체를 꺼낸 뒤, 해당 객체의 가격(Price) 값을 가리키는 **`.p`** 속성을 가져온 것입니다.

---

### Q10. `useEffect` 리턴 문 안의 `unsubscribe`와 `ws.close()`는 무엇인가요?
* **사용자 질문**:
```javascript
return () => {
  if (ws.readyState === WebSocket.OPEN) {
    ws.send(JSON.stringify({ type: 'unsubscribe', symbol: selectedSymbol }))
  }
  ws.close()
}
```
이건 뭐 하는 거야?
* **답**: **웹소켓 전화선을 깔끔하게 끊어주는 정리(Clean-up) 코드**입니다.
  사용자가 주식 종목을 'AAPL'에서 'TSLA'로 바꾸거나 페이지를 나갈 때, 이전 종목의 실시간 알림 구독을 취소(`unsubscribe`)하고 열려 있던 웹소켓 소켓 연결을 닫아(`ws.close()`) 메모리 누수와 이전 종목 소식이 섞이는 버그를 방지합니다.

---

### Q11. `const newPrice = parseFloat(price.toFixed(2))`는 무엇인가요?
* **사용자 질문**: `const newPrice = parseFloat(price.toFixed(2))` 이건 뭐야?
* **답**: 
  1. `price.toFixed(2)`: 숫자를 소수점 둘째 자리까지 반올림합니다. (주의: 결과가 `"182.50"` 같은 **문자열**로 변환됨)
  2. `parseFloat(...)`: 문자열 `"182.50"`을 다시 차트 계산이 가능한 **숫자 타입 `182.5`** 로 되돌려 줍니다.

---

### Q12. 처음 키고 차트가 계속 옆으로 밀려나면서 갱신되어야 하는데 왜 안 밀려나나요?
* **사용자 질문**: 처음 키고 차트가 계속 옆으로 밀려나면서 갱신되도록 한 건가? 왜 안 그러지?
* **원인 및 해결**: 
  * Finnhub 웹소켓은 **미국 주식 시장 개장 시간 (한국 기준 밤 11:30 ~ 아침 06:00)** 에만 실시간 체결 데이터를 보냅니다. 따라서 한국 낮 시간대에는 웹소켓 연결은 정상이나 체결 소식이 오지 않아 차트가 멈춰있었던 것입니다.
  * 이를 해결하기 위해 장 마감 시간대이거나 키가 없을 때 **2초마다 시세 API를 호출하는 2초 폴링(`setInterval`) 폴백 로직**을 추가하여 낮 시간에도 2초마다 차트가 우측으로 밀려나도록 보완했습니다.

## 💡 핵심 문법 & 오답 노출 체크리스트

| 문법 / 패턴 | 설명 | 주의 사항 |
| :--- | :--- | :--- |
| **`document.documentElement`** | 최상단 `<html>` 태그 참조 | DOM 직접 조작 시 컴포넌트 위치와 관계없이 전체 페이지에 적용됨 |
| **`let alive = true; return () => { alive = false }`** | 비동기 취소표 패턴 | 광속 클릭 시 이전 비동기 fetch 응답이 현재 화면을 덮어쓰는 것 방지 |
| **`data[data.length - 1]`** | 배열의 맨 마지막 요소 참조 | 차트 등 시간 순서 데이터에서 가장 최근 데이터 포인트를 가리킴 |
| **`prev.slice(-59)`** | 슬라이딩 윈도우 | 뒤에서 59개만 잘라내어 배열 크기를 최신 60개로 계속 고정 |
| **`parseFloat(num.toFixed(2))`** | 소수점 정리 & 타입 변환 | `.toFixed()` 사용 후 반드시 숫자 타입으로 복구할 것 |
