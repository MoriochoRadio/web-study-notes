## 확인한 것 — Day 9

이 PC에는 10/23까지 `langchain` 패키지가 없었는데 10/26에 `langchain 1.4.7` · `langgraph 1.2.17`이 설치돼 있어 `create_agent`를 실제로 실행할 수 있었다. LLM은 부르지 않고, 정해 둔 `AIMessage`를 차례로 돌려주는 **가짜 모델**(`GenericFakeChatModel`에 `bind_tools`만 더한 것)을 달았다. 그래서 확인한 것은 `create_agent`가 LLM의 판단 결과를 받아 도구를 실행하고 메시지를 쌓는 **틀**이고, LLM이 실제로 올바른 도구를 고르는지는 아니다.

| 항목 | 방법 | 결과 |
|---|---|---|
| 도구 단독 | 노트북 칸 0의 도구 정의를 그대로 실행 | `get_weather` 서울 → 맑음, 23도 · 부산 · 대구 → 정보 없음. `calculate`: `10 * (2 + 3)` → 50, `3 + 5 * 2` → 13, `-5 + 2` → -3, `(1 + 2) / 4` → 0.75 |
| `calculate`의 거부 | 14가지 입력 | `2 ** 3` · `5 % 2` · `10 // 3` · `1 / 0` · `7 곱하기 8` · `2 + ` · `3; 4` · `__import__('os').getcwd()` 모두 "계산할 수 없는 수식입니다." — 허용표에 없는 연산자(`KeyError`) · 0 나누기 · 문법 오류 · 함수 호출이 한 문구로 뭉뚱그려짐. 반대로 `'a' + 'b'`는 `'a' + 'b' = ab`로 계산됨(`ast.Constant`가 문자열도 받음) |
| 메시지 흐름 | 가짜 모델 + 도구 한 번 | 4개 `[HumanMessage, AIMessage, ToolMessage, AIMessage]`, `[1].tool_calls` 모양, `ToolMessage.name`, `ToolCall`로 도구를 직접 부르면 `ToolMessage`. 모델이 받은 글: 첫 호출 `[System, Human]`, 둘째 호출 `[System, Human, AI(tool_calls), Tool]` → 도구 한 번 = LLM 두 번 |
| 도구 없이 답 | 가짜 모델이 바로 답 | 메시지 2개 `[Human, AI]`, `[1].tool_calls == []`. 네 질문(제주 날씨 · 125 + 375 · 수료증 · 기분)에서 각각 도구 `get_weather` · `calculate` · `search_notice` · 없음, 메시지 4 · 4 · 4 · 2 |
| 입력 모양 | `"messages"`에 딕셔너리 하나(선생님 노트북 12쪽 칸이 그렇게 씀) | 통과(`HumanMessage`로 바뀜). `system_prompt`를 안 주면 모델이 받는 글은 `[Human]` 하나 |
| 검색 도구 | 글자 2-gram 장난감 임베딩 + `search_notice` | 항상 k=2개(관련 없는 "오늘 날씨"에도), 검색 도구를 단 Agent는 메시지 4개 |
| 모서리 | 가짜 모델 | tools에 없는 도구 이름 → `ToolMessage("Error: get_stock is not a valid tool, try one of [get_weather].", status="error")` 후 다시 판단(메시지 4개). **도구가 예외를 던지면 `invoke`가 그 예외(`ValueError`)로 끝남**. 도구만 계속 부르면 `recursion_limit=10`에서 `GraphRecursionError`. 한 번에 도구 둘 → `ToolMessage` 둘, 메시지 5개. 도구를 두 번 연달아 → 메시지 6개 |
| `llm` 설정 | 노트북 코드 · 실행 번호 읽기 | 칸 1은 `temperature=0`, 칸 4가 `llm`을 `temperature` 없이 다시 만들고(`ChatOpenAI`의 기본값 `None` = 서버 기본) 이후 칸의 `agent`가 이를 써서 같은 질문의 답이 실행마다 조금씩 다름(제주 날씨 답이 칸 6과 7에서 다른 문장). 칸 3은 실행 번호 9로 나중에 다시 돌렸음 |

## 확인하지 않은 것

- 실제 OpenAI 임베딩 · LLM 호출(요금 · 키). 노트북의 답 · 검색 결과는 저장된 그대로이고, **LLM이 실제로 올바른 도구를 고르는지 · 어떤 문서가 1등으로 검색되는지**는 저장된 출력으로만 안다.
- 교안 17쪽 종합 실습은 선생님 노트북에도 풀이 코드가 없다(안내 주석뿐). Day 8 · Day 9 실습예제는 둘 다 풀지 않았다.
- 선생님 Day09 노트북 15쪽 칸의 `ToolMessage` 출력은 저장된 출력이 길게 잘려 있어 검색된 문서의 순서는 확인하지 못했다.
- 이 PC의 `langchain` 설치 시점은 10/23(없음)과 10/26(1.4.7) 사이로만 안다.
